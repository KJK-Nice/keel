# The native window

The Keel window is a native window drawn with [MyGo](https://github.com/egoist/mygo) (pure Go, purego, no cgo) and libghostty terminals. `keel app` opens it in the same process as `keel` (`internal/app/run_native.go` calls `native.RunWith`); `cmd/keel-native` is the same window as a separate binary that attaches to a running `keel serve`. It is the only UI: the daemon serves no web page. This file is the UI document: what the window is, how to run and verify it, what each area does, and what it does not do. `docs/ui-redesign.md` holds the screens, the agent invariants (§6) and the design intent; its section numbers are cited throughout the code.

The window is a client only. `keel serve` owns SSH and the PTYs, and the window never reads the keychain or the vault: it sees what `keel serve` returns on loopback, with the token from the data directory (`X-Keel-Token`, never a cookie or an `Origin`).

## Run it

```sh
make build              # bin/keel, and the shipped app in build/<os>-<arch>/ (make package, below)
./bin/keel app          # or just ./bin/keel, or open build/darwin-*/Keel.app; make app from a checkout
```

`keel app` makes the data directory (0700), loads or creates the token, starts `keel serve` if it is not running (`EnsureServe`) and checks that it answers to that token (`VerifyServe`). It then opens the window on that address and data directory (`KEEL_ADDR`, `KEEL_DATA`, from `internal/paths`, as for `keel serve`). It needs no signed bundle, so a bare `./bin/keel` works, but it has no bundle icon or name in the Dock and menu bar; `Keel.app` has (made by `mygo build` from `mygo.json` and `packaging/macos/`; its entitlements are `disable-library-validation` only, which lets the ad-hoc app load its libghostty-vt dylib). `--name` sets the share name for the run (it sets `KEEL_NAME`, which the window reads for Settings · Sharing and for its sessions).

If the `keel serve` that answers is from another build than the app, the window shows a toast ("The Keel runtime that's running is from a different build than this app…") and a **Stop runtime** button that asks first. The build id is `internal/buildid.Of`: the VCS revision of a clean build; for a build from a modified tree (`+dirty`) or with no revision (`go run`, `go test`) the revision, if any, plus a hash of the running binary, so two different dev builds still differ. `keel serve` and `keel app` are the same executable, so both compute the same id; a `keel serve` left over from an older binary has another one. The toast lasts the usual five seconds.

The fonts (JetBrains Mono, IBM Plex Mono) are embedded (`internal/native/fonts`, with their OFL files), so the bundle needs no font files beside it. A binary that has no libghostty-vt beside it (a bare `./bin/keel`, `go run`) downloads it into the user cache on first run (SHA-256 checked by MyGo); the packaged app (`Keel.app`, the Linux archive and `.deb`) carries it, so it never downloads.

### Packaging

`make package` (and `make build`) runs `go tool mygo build` (MyGo's CLI, a `tool` line in `go.mod`), configured by `mygo.json`: name `Keel`, slug `keel`, identifier `app.keel.desktop`, main package `./cmd/keel`, icon `packaging/macos/icon.png` (and `Keel.icns` for macOS), macOS 13 or later, the entitlements and `ApplePressAndHoldEnabled=false`, `LICENSE` and `THIRD_PARTY_NOTICES` as resources, GTK 3 and no WebKitGTK on Linux (`linux.webview` is `false`; MyGo's default is `true`). MyGo compiles (`-trimpath`, no cgo, `darwin/universal` for both CPUs), builds the bundle and signs it, and puts libghostty-vt for the target in the package from the terminal plugin's `mygo-plugin.json` (SHA-256 checked, cached in the user cache of the build machine): `Contents/Resources/libghostty-vt.dylib` in the app, universal, and `libghostty-vt.so` beside the binary on Linux (the plugin's loader finds both before it would use the user cache). The binary inside the app is `Keel.app/Contents/MacOS/Keel` and still runs `keel serve`, `keel mcp` and `keel version` (macOS's file system finds `keel` too, case-insensitively). The bundle id stays `app.keel.desktop`: changing it would orphan the Keychain items and user defaults tied to that id. A package has no automation plugin (`MYGO_AUTOMATION` is ignored): `make native-automation` runs its own `bin/keel-e2e`. The release (`scripts/release.sh`, `docs/release.md`) is the same `mygo build` for `darwin/universal`, `linux/amd64` and `linux/arm64`; MyGo's `PKGBUILD` and `install.sh` are not published (a `PKGBUILD` hashes one archive of one CPU, and `install.sh` installs from MyGo's update manifests, which Keel does not have).

### The app shell

The window's shell (`internal/native/shell.go`; the menu items run the window's own actions and add no writer):

| Shell behaviour | Window |
|---|---|
| App menu (About, Hide, Quit ⌘Q), Window menu | MyGo `RoleAppMenu`, `RoleWindowMenu` |
| File menu: New Tab ⌘T, Close Tab ⌘W, Reopen Tab ⌘⇧T, New Host ⌘N, Quick Connect ⌘⇧O, Join Session ⌘J, Split Right ⌘⇧D, Split Down ⌘⇧E, Split Notebook, Close Window ⌘⇧W, Stop Keel runtime | built; Find Host has no chord and is the sidebar filter and the palette |
| View menu: Find in Terminal ⌘F, Toggle Vault Sidebar ⌘B, Toggle Agent Panel ⌘I (Ctrl+⇧I off macOS), Focus View ⌘⇧↵, Zoom In ⌘= / Zoom Out ⌘- / Actual Size ⌘0 | built; the chords are the window's own (the command table, `commands.go`), and a chord that is a menu item's goes to the menu, which runs the same function |
| Edit menu | none on purpose: its ⌘C/⌘V roles would take the keys from the terminal's own copy and paste |
| Menu bar item (tray) with serve status, Show/Hide, New Tab, Quick Connect…, Allow Claude Code, Quit Keel | macOS only (MyGo `NewTray`, a template icon) |
| Keep in menu bar: closing the window hides it and the Dock icon, the menu bar item or opening Keel again brings it back, Quit quits | macOS only (`Window.OnClose` + `App.Dock.Hide/Show` + `App.OnActivate`) |
| Window size and position remembered | `WindowOptions.StateKey` "main", `App.SetWindowStateStore`: `window-state.json` in `KEEL_DATA` beside `keel-native.json` holds the frame, MyGo ignores a frame that is off every connected display, an entry with no usable size is dropped and full screen is not restored (`windowstate.go`) |
| Single instance | not used (MyGo has `RequestSingleInstanceLock`) |
| Appearance follows the OS and the theme choice | `mygo.Theme.SetSource` |
| Full screen, traffic lights, translucent window and blur | built |
| Close the window to detach; sessions stay in `keel serve` | `closeWindow` detaches |

The headless tester cannot reach the menu bar, tray, Dock or close behaviour; `make native-automation` chooses the menu items, and the rest is on the person-only list at the end. `shell_test.go` covers the tables: labels, chords per OS, and that each action does what its chord does.

## Verifying

`make native-e2e` builds `bin/keel` (with the build tag `keelfake`, which links the agent's fake provider), `bin/keel-sshtest` and `bin/keel-signal`, and drives the real window under MyGo's `ui.Tester` against a scratch `keel serve` it starts per test (scratch data in `.scratch-native/e2e/`, one PNG per scenario). It needs macOS and does not touch your Keel. CI runs it on a macOS runner and it must pass. Test builds: `make build` replaces the tagged `bin/keel`.

### Linux

CI runs `make test` on Ubuntu as well as macOS, the window's package (`keel/internal/native`) included. Nobody has run the window on a Linux desktop. What is known about the Linux text path and layout:

- MyGo draws text on Linux with Pango, cairo and fontconfig loaded at run time with purego, and falls back to a stub engine (text does not show, widths are zero) when they are missing. The runner has them, with DejaVu Sans and DejaVu Sans Mono, and `libghostty-vt` is downloaded at run time and loads (terminals run).
- The theme's default UI family is `system-ui`: the desktop's interface font or, with none, fontconfig's default sans (DejaVu Sans on Ubuntu), wider than macOS's. Layouts are checked against both: the Agent page's root has `MinWidth(0)` so its content cannot set its width; the narrowest sidebar is `sidebarFontSlack` (6 px) wider off macOS so its four labels fit; the test sets that assume macOS metrics sample by region or column instead of fixed points.
- **The bundled JetBrains Mono and IBM Plex Mono are not used on Linux** (`registerFonts` registers nothing there; the stacks fall back to the system monospace). For a registered JetBrains Mono file the advance of every glyph was 25 px at 6.5 px, 15 px at 13 px and 23 px at 26 px, while the system monospace gave 4, 8 and 16, so the advance does not follow the size and the glyphs probably do not come from the file (perhaps the runner's FreeType does not decode the woff2). The cause is not found: `TestDiagRegisteredFontMetrics` logs the advances, and `TestShippedFamiliesRenderDifferently` skips on Linux for this reason. A registered file is also known process-wide under its own family name and cannot be unregistered, so the terminal-cell tests ask for the system mono stack off macOS (`gateStack`).
- Keys and labels off macOS use Ctrl and Shift (`Ctrl+Shift+Z`, `Ctrl+Shift+Y`, `Ctrl+Shift+I`; `ui.Cmd` is Ctrl there and Ctrl+Z is the shell's): the command table and the key-label helpers produce them, and tests press `agentMods()`. The hint after a plain Tab on a destructive suggestion reads "Shift+Tab".
- A typed key that the plugin delivers as text alone (Linux) is not seen by `OnKey`, so the suggestion typing pause starts at the next key it does see.
- There is no blur (the window is translucent, not blurred), and the theme follows the OS only where the window can take it (macOS).

### Driving the built app from outside

`make native-automation` builds `bin/keel-e2e` (the build tags `keelautomation` and `keelfake`) and runs `tests/native-automation` (tag `nativeautomation`, so `go test ./...` never runs it). It starts the real window on scratch data and drives it through MyGo's automation socket (`MYGO_AUTOMATION`, newline-delimited JSON; the tests speak the protocol directly). It opens real windows for a few seconds each, so run it where a window can open. It covers what `ui.Tester` cannot: First run in a real window; every File and View menu item of `shell.go` chosen through the menu bar, with New Tab, Split Right/Down, Toggle Vault Sidebar and Toggle Agent Panel checked in the tree; Close Window hiding the window while the app runs; real key events into a real terminal (read back from keel serve's scrollback, because the terminal's text is not in the tree); both themes captured from the real window (`.scratch-native/automation/`); and the run-time guard. The scenarios that judge screen pixels (`TestWindowHasNoShadow`, `TestNoGhostUnderLowOpacity`, `TestTerminalCursorAndSelectionAreNotBrass`) run only on a developer's Mac: they skip when `GITHUB_ACTIONS` is `true`, because the runner's `screencapture` is not a faithful photo of the composited window. Not covered: Show from the menu bar item or the Dock (neither is reachable through the socket), and a paste with Sync input (the protocol has no clipboard call, and no test touches the system clipboard).

**Security.** The socket lets another local process type into the app, so it exists only in test builds: the import of `plugins/automation` is in `cmd/keel/automation.go` and `cmd/keel-native/automation.go` behind `//go:build keelautomation`, no release path passes the tag, and tagged builds refuse to run unless `MYGO_AUTOMATION` is in a directory of mode 0700 and `KEEL_DATA` names a directory other than the default one (`native.CheckAutomationEnv`, called from an `init` of package main). MyGo's plugin listens in its own `init`, which runs before ours, but it answers nothing until the app has launched and our `init` exits before that and removes the socket. `internal/native/autoenv_test.go` proves each part (`go list -deps`, the importing files, the Makefile and scripts, the check). The fake agent provider has the same shape: the tag `keelfake` is passed only by the two test targets of the Makefile (`internal/app/agent_real_test.go` checks it), and any other build refuses to start `keel serve` with `KEEL_AGENT_PROVIDER=fake`. Never run `bin/keel-e2e` against real data, and never distribute it.

## What the window does

### Workspace

- Host tree grouped by group, with a filter on name, address and username. Click a host to open it in a new tab (or in the New tab that is showing).
- Tabs with a state dot, a pane count badge and a close button (16 px, shown while the pointer is over the tab; with ⌘ held the W cap stands in for its glyph on the selected tab); `+` and ⌘T open a New tab (below).
- Split → and Split ↓ (another PTY to the same host), drag the gap to resize, close a pane (kills its PTY; the last pane closes the tab). Drag a pane bar onto another pane of its tab: an edge moves it beside that pane, the centre swaps the two, the region it would take is drawn while the pointer is over (`panedrag.go`, `layout.Beside` and `Swap`). A tab dropped on the empty strip after the last tab goes last. A pane dragged by its bar and let go on the strip (a tab, or the empty strip) becomes a tab of its own there (`extractPane`; a tab of one pane has nothing to leave), and a tab dropped on a pane of another tab docks all its panes beside that pane (`dockTab`, `layout.Dock`; the centre docks to the right; the region is drawn as for a pane), with Sync input on if either tab had it. No session is opened or closed by either (`panedock_test.go`). Joined tabs, the New tab page and page tabs take no part; notebook tiles are neither dragged nor dropped on.
- Splits fit the window. Any split tree tiles the stage: every tile lies inside it, siblings are 6 px apart and each split's two sides share its width (or height) in its ratio, at any window size; a window too small for the tiles makes them narrower and clips their pane bars, and nothing runs off the edge. Each split divides the room it has by its own ratio, so four panes in a row are 1/2, 1/4, 1/8, 1/8 of the width until you drag a gap.
- Live terminals; the focused tile gets the soft ring and the others dim in a split tab.
- **Sync input**: the pane bar's sync tool (pressed, "Sync input" / "Stop syncing input"; every terminal pane of a syncing tab shows it pressed, the only look sync has), the status bar's "Sync on" / "Sync off" (not in a joined tab), and the palette's "Toggle sync input" (offered only in a session tab with a terminal; there is no shortcut). While a tab has it on, the user's own keys and paste in one terminal go to every other terminal pane of that tab that this client drives and that is ready, as well as to the pane typed into. The flag is saved with the tab (`sync` in `keel-native-workspace.json`). How it is built, and why it is not an injection: "How Keel types for you" (the fifth writer).
- The workspace comes back. The tabs, how each is split (direction and ratio), custom tab titles, the focused and zoomed pane of each tab and the active tab are saved in `keel-native-workspace.json` in the data directory (session ids, titles and layout only: no host, user, address or secret; mode 0600, written atomically, debounced and on window close). A window reopens with the same tabs and splits. Sessions that are gone drop out of their tab and the tree closes up; running sessions that were in no saved tab become tabs after the saved ones; a missing, unreadable or other-version file gives one tab per session. A restarted `keel serve` gives new session ids, so nothing restores after a daemon restart. Closing the window detaches; sessions keep running.
- Title bar, right: the bar status: "<pane line> · driving" (or "· following") for a session, "New tab" or "Connecting…" on the New tab page, "No session", nothing on a page. Status bar: session count, the running forwards (`N forwards`, hidden with none), focused pane size, encoding.
- Focus view: ⌘⇧↵ or the pane bar's Focus view tool shows the focused pane alone and keeps the others' sessions; splitting or closing the zoomed pane leaves it.
- The pane menu, from the pane bar's **More pane actions** tool or a right-click on the pane bar: Split right, Split down, Focus view (with another pane beside it, or while zoomed), Share (for a live local session), Reconnect (for a failed session), Close pane. ⇧F10 and the Menu key open it from a focused control of the bar (MyGo's popover menus take them); in the terminal ⇧F10 stays the program's.
- The tab menu, from a right-click on a tab: Rename tab, Close, Close others, Close to the right, Close all. Rename edits in place: Enter or a click elsewhere keeps the name, Escape cancels, an empty name clears the custom title. Closing a tab kills its panes' sessions.
- Drag a tab onto another to reorder (it lands before or after it by which half the pointer is over); ⌘1…⌘9 follow the order. ⌘⇧[ and ⌘⇧] (also ⌘< and ⌘>) select the previous and next tab and wrap.
- ⌘⇧T reopens the last closed tab or pane as a new session on the same host, in a new tab or in the New tab that is showing (up to 10 are remembered for this window; none across a window close).
- ⌘F finds in the focused terminal with the terminal's own search: a find bar above it with the match count, previous and next, and close. Enter and ⌘G go to the next match, ⇧Enter and ⌘⇧G to the previous, Escape closes. Nothing is sent to the session. There is no Match case (see "What the window does not do").
- ⌘+ (⌘=), ⌘- and ⌘0 set the terminal text size of every pane, 10 to 22, default 12, kept as `termSize` in `keel-native.json`.
- Pane states. **While a pane's session is not ready (connecting, failed, lost, reconnecting) its terminal view is not built**: the pane shows its ground and the connection log, so the last picture of the terminal is not readable through the overlay in a translucent window and no caret blinks; the terminal object and its scrollback stay alive, only the view is out of the tree, so nothing typed reaches it. A joined pane keeps its view. When the session is ready again the view returns and the pane takes the keyboard back if it had it (`pane.regain`). Held by `panelost_test.go` and `TestE2ELostWhileOpenShowsNoTerminalBehindTheOverlay`. A session that is down (exited, or failed) shows a flare banner, "Session ended", "Connection lost" or "Connection failed", with its endpoint and the server's last message, and **Copy logs**, **Close**, **Edit host** and **Reconnect**, and under it the connection log over the pane: the lines the window seeds ("Starting a new connection to: "addr" port "22"", "Starting address resolution of …", "Address resolution finished", "Connecting to …"; "Starting a local shell" for a local one) and the lines keel serve reported (`keelclient/log.go`: noise dropped, a repeat dropped, the last 40 kept, forgotten when the session is ready, begun again by a reconnect), each with its glyph (a failure in the flare colour). **Copy logs** puts those lines on the clipboard and says "Copied connection log". Sessions that were already down when the window opened come back as tabs with that banner. A non-local session that is connecting shows a signal "Connecting…" banner with the log and Copy logs, Close and Edit host.
- A first connection to an unknown host key, or a changed key, opens a dialog for the focused pane: host, key type, fingerprint (and the saved one for a changed key). **Trust and connect** sends the server's own offer back and reconnects; **Abort** or Escape leaves the pane with its banner. Nothing else trusts a key.
- A session another window also attached shows a role chip (Driving, Owner, Following, each with its glyph: steering for who drives and the owner, an eye for a follower) in the pane bar. Anyone who is not driving sees a haze banner ("Following · <name> is driving · read-only", or "Nobody is driving") with **Take control** for the session's owner and **Ask for control** for everyone else; keel serve drops a follower's keystrokes, and so does this client: a connection that does not drive sends nothing, counts the keys it dropped, and the window says "Typing is off while you follow" with **Take control** or **Ask for control** (a toast at the bottom right).
- Toasts: bottom right, the newest three, 5 s each (the timer stops while the pointer rests on them), an alert icon on a failure, a close button, and one optional action button. Results are toasts: Host saved, Duplicated as …, Identity saved, Snippet saved, Forward saved, Host key saved, Host key forgotten, Copied, the import's result, "Open a session first" and the failures of a call (the server's own reason).
- The host list stays current. The hosts are read again after every write the window makes, and a poll of `GET /api/vault` every 3 s while the window is open reads them again when its `rev` changes; the filter, the collapsed groups and the open tabs stay. If the poll finds the vault locked again, the Unlock screen covers the window and sessions and tabs stay as they were; if another window unlocked it, the screen goes away.
- The area outside a tile's rounded corners is chrome under window translucency, once.

### The command palette and the New tab page

- The command palette, ⌘K or ⌘⇧P: the input, then **Open now** (every tab, and each pane of a split tab, with its state dot; choosing one focuses it and never starts a session), **Hosts** (↵ a new session in a new tab, ⌥↵ in a split right of the focused pane) and **Actions**. Every word of the query must appear in a row's title, hint, group or keys; the matched text is highlighted. ↑ ↓ wrap and keep the row in view, ↵ runs, esc (or ⌘K again) closes and returns the keyboard to the pane. While it is open no key reaches a terminal and no window shortcut acts. Actions it has: New tab, New Local Shell, Close pane or tab, Reopen last tab, Previous tab, Next tab, First tab, Last tab, Toggle vault sidebar, Search hosts (the sidebar shows Hosts and its filter has the keyboard), Quick connect, Split right, Split down, Focus view (zoom pane), Find in terminal, Larger text, Smaller text, Reset text size, and the pages, Join, Share, Import and Stop runtime named below. The last row, **Ask the agent** (⌘↵, Ctrl+↵ off macOS; the footer's "ask agent" cap), is there whatever the query matches, with no group heading: it opens the agent panel with the query in the composer and **sends nothing** (the panel with no key shows its Connect card). With nothing matched the list says "No matching commands" above that row. The palette's host rows match their title and `user@address` only.
- The New tab page (⌘T, `+`, and what an empty window shows; closing the last tab leaves one, and ⌘W on the lone New tab does nothing). "Where to?", one input (a saved host, `user@host:port`, or a pasted `ssh …` command), the recent host cards (up to 6, `⌥1`-`⌥6` open them; the local shell is always first; a query filters every host by name, group, the names of the folders above it, address, user and tags, recent ones first), the **Start** action Quick connect (⌘⇧O), and **Recently closed** (up to 3, with their age; a row, or ⌘⇧T for the newest, starts a new session on that host). ↵ opens the highlighted card (↑ ↓ move it). Opening a host fills the New tab that is showing. A New tab is not written to the saved workspace. Recent hosts are kept as host ids only, newest first, up to 12, as `recentHosts` in `keel-native.json`. Recently closed is kept across closing the window as `closedTabs` there (a host id, the title cut at 120 characters, "tab" or "pane" and a time).
- ⌥1…⌥6 work with the caret in "Where to?" too: a Mac types the key's character ("™" for ⌥2) into the input before any window shortcut runs, so the page notes the cards and the text as the key found them, opens that card, and puts the text back (`tests/native-automation/altnumber_test.go`).
- A pasted command is parsed, never run (`internal/native/sshparse`): no shell, no `ssh` binary, no key file read, no lookup. The page shows "Read as `user@host:port`. Nothing has run.", what was **left out** and why (a command that runs something, host-key trust changes, forwards, a jump host, config files, a remote command) and a key-file note. **Connect once** (needs a user) opens the Quick connect dialog: the target is prefilled, the user types the password (never taken from the pasted text), and **Connect** saves a password host named `user@host` in the group "Quick connect" with `POST /api/hosts` and opens it; the host key dialog follows. Quick connect (⌘⇧O, the Start action, or the palette) is the same dialog with an empty target; its target is read with the same parser, which takes `user@host`, `user@host:port`, `ssh://…` and a pasted command.

### Keys

One table (`commands.go`): each command's key is written once, and the shortcut, the menu bar item, the palette row and the Keyboard page row are made from it. Labels are ⌘⇧T on macOS and Ctrl+Shift+T elsewhere. The keys: ⌘1…⌘8, ⌘9, ⌘W, ⌘T, ⌘N, ⌘K, ⌘⇧P, ⌘⇧O, ⌘⇧D, ⌘⇧E, ⌘⇧↵, ⌘⇧T, ⌘⇧[ ⌘⇧], ⌘F, ⌘G, ⌘⇧G, ⌘+ ⌘- ⌘0, ⌘B, ⌘I (the agent panel; Ctrl+⇧I off macOS), ⌘Y (Suggest a command for this line; Ctrl+⇧Y off macOS), and ⌥1…⌥6 on the New tab page (Ctrl off macOS). ⌘G, ⌘⇧G, Escape in the find bar, ⌥1…⌥6 and Escape on the New tab page are written by hand and appear on no menu or list. `docs/shortcuts.md` lists them for users.

While ⌘ (Ctrl off macOS) is held 280 ms every element that has a cap gets one: tabs 1 to 8 and 9 for the last, `+` (T), the sidebar toggle (B), New host (N), Settings (,) and the focused pane's Split right (⇧D), Split down (⇧E) and Focus view (⇧↵, not while disabled). Caps fade in over 120 ms (at once with reduced motion) and go at once on release, on another key, on a click and when the window loses focus; a key already down when the hold began (a menu shortcut's lost release) does not count. They show under dialogs and in text fields. A cap is the flat key cap of "Look" below: `raised`, a 1 px `line-strong` border all round, opaque, so it reads on any ground; it **stands in for the icon or status dot** it covers, centred on it, and never a label. A cap on a tab hides the tab's dot or icon while it shows. Settings · Terminal's text-size row shows "+ − 0" in place of the value. The "W" cap on the selected tab's close button stands in for its glyph. The Agent and Share buttons have no cap.

### Appearance and preferences

- Preferences live in `keel-native.json` in the data directory, one typed document (`prefsDoc` in `prefs.go`) loaded once when the window starts and written only through `w.savePref`; a key this version does not know is kept when the window writes. Its fields include `opacity`, `blur`, `theme`, `uiSize`, `termSize`, `termFont`, `copyOnSelect`, `rightClick`, `name` (Settings · Sharing), `recentHosts`, `closedTabs`, `groupCollapsed`, `sidebarWidth`, `agentWidth`, `agentPanel`. Every setting writes its own field and leaves the others as they are.
- Window translucency: the window is see-through at the saved opacity (default 66, range 30-100) with a macOS background blur (default 20, range 0-64; a private window-server call that falls back to no blur and logs once to stderr); the blur is set when the window shows and again when Settings changes it.
- Appearance · Theme: System (the default; it follows the OS appearance and changes with it), Light or Dark. `tokens.go` holds both colour sets (`TestTokensMatchJSON` checks them against `docs/design/tokens.json`) and `useTheme` sets the colour variables at the start of each frame, so a view never names a theme. Everything follows: grounds, text, lines, MyGo's stock widgets, every open terminal's colours (`Terminal.SetTheme`), dialogs, toasts, the palette, the pages, Unlock and First run, the translucent grounds (the light terminal body keeps 30% of the see-through, `vibrancy-term-share`), and on macOS the window's own appearance (`mygo.Theme.SetSource`, so the backdrop follows the choice). Where the window cannot take the theme (not macOS), a theme that differs from the OS's keeps the window opaque, and Settings says so; on macOS that line is hidden.
- Appearance · UI size, 11 to 16 (default 12), kept as `uiSize`. It scales text, icons, key caps, dots, the role chip, the radio, the host tile, the palette's width and the tab's widest, and the Settings sliders (a design px is `px × size / 13`). It does not scale the title bar, tab, pane bar and control heights, the sidebar and rail widths, the spacing and the radii, or the terminal (its text size is separate). There is no key for it.

### Unlock and First run

- Unlock (§5.14). A vault that exists and is locked (the keychain did not answer, or it uses a passphrase) shows the Unlock screen in place of the window: the mark, "Unlock your vault", the lead with the number of sessions waiting in keel serve, the banner for the vault's mode (keychain vault, `KEEL_KEYRING=off`, or a keychain that does not hold the key), the masked "Vault passphrase" field with a show/hide control, **Unlock** (↵), and the two statements (a lost passphrase cannot be recovered; running sessions keep working). A wrong passphrase shows "That passphrase doesn't open the vault." and keeps the keyboard in the field. The passphrase is sent in the one `POST /api/vault/unlock` and cleared from the field when it is sent; it is in no log, file or error. A locked vault shows Unlock whatever its first-run flag says. A vault that still needs setup, and an unlocked vault whose first run is open, show First run (next).
- First run (§5.15). A vault that needs setup, or whose first run is open, shows three steps in place of the window, under a progress row Vault · Hosts · Agent. **Step 1** is "Welcome to Keel": the keychain card and the passphrase card, the Passphrase and Repeat passphrase fields (with "Choose a passphrase." and "The passphrases don't match." before any request, and the server's own words after one), "Keel can't recover the vault if you lose the passphrase.", the vault file, its encryption and what it holds, **I already have a keel.vault…** (instruction text only: it quits, puts the file in the data folder and opens Keel; no file picker), and **Create vault** (`POST /api/vault/setup` with the passphrase, once). The keychain card is the choice already made: with `KEEL_KEYRING=off`, or when the keychain did not answer, it is disabled with the reason; on a vault the keychain made, it is the checked card and the button says **Continue**. keel serve makes a keychain vault itself, so there is no request for that choice (and a machine test cannot make one: the harness runs with `KEEL_KEYRING=off`). **Step 2** is "Bring your hosts": the table of `GET /api/ssh-config/preview` with a checkbox per host (the rules are in `onboard.go` and its test: new direct hosts start ticked, saved hosts and ProxyCommand/ProxyJump hosts start off, "Already saved", the Via flag and **Without the jump**, wildcard patterns listed apart, the notes, select all), then **Copy private keys into the vault** (one switch per key, off by default, a masked passphrase field for an encrypted key, "Enter the passphrase for <key>, or turn this key off.", "That passphrase doesn't open <key>."). **Add hosts** sends exactly the ticks and the keys turned on (`POST /api/ssh-config/import`); the result ("Added 2 hosts and 1 key. Not added: …") shows under the next step. **Back**, and **Skip, add hosts later**. The server reads the ssh config (`KEEL_SSH_DIR` in keel serve); the client never opens `~/.ssh`. Key passphrases and the vault passphrase are sent once and cleared when sent. **Step 3** is "An agent that suggests, never types": the three promises, then **Provider** (Google Gemini or Not now, the radio cards; Not now is chosen), when Gemini is chosen its warning, the masked "Gemini API key" field (it takes the keyboard), "Get a key" and "Gemini API terms", and the switch "Suggest commands when I type plain language" (on). **Open Keel** sends the key once (`PUT /api/agent/keys/gemini`; keel serve does not check it with the provider, and the field is emptied as it is sent) and the switch (`PUT /api/agent/settings` with `suggestions` alone), then `POST /api/first-run/done` and the workspace; with Gemini chosen and no key it says "Paste your key, or choose Not now."; a refused save (a locked vault: "The vault is locked. Unlock it, then try again.") stays on the step with keel serve's reason. **Back**; **Set up later** saves nothing and only ends the first run (`POST /api/first-run/done`). A second window on the same daemon opens straight to the workspace. The command palette's **Import hosts from ~/.ssh/config** opens step 2 on its own (title "Import hosts", **Cancel** and Esc instead of Skip, no progress row or Back), and its result shows in the status bar.

- Snippets (§5.12). The Snippets page: a list (name and first line) with a filter and **New snippet**, and the selected snippet's editor: its name, **Type into pane…**, **Save** (⌘S), the Commands text area ("One command per line. The row menu is Type into pane…, Copy, Edit, Delete; New and Edit open the snippet dialog (Name, Command, **Save snippet**). A save trims the name and ends the command with a newline. The palette badges "Approve first" only the snippets that will certainly ask (more than one line, or outside the direct grammar). **Type into pane…** uses the saved snippet, not unsaved editor text. ⌘N on the page is New snippet.
- The Keychain page (§5.11). A list (SSH keys, then Passwords, each row with its kind, user and "N hosts", and a "passphrase" badge) with a filter and **New identity**, and the selected identity beside it: kind and date added, Username, what is stored ("Encrypted in the vault", "Stored in the vault", "Not stored", "None"), the hosts that use it, **Edit** and **Delete identity**. The identity dialog has Name, Username, Kind, then a Password, or a Private key and a Key passphrase; blank secrets are left out so the server keeps the saved ones; the secrets are cleared when it closes or the request is sent. The page never holds, shows or copies a private key, a passphrase or a password: `keelclient.Identity` has no field for one. Secrets are never written here.", a search box (kind and message), the chips All, Sessions, Forwards, Vault and Agent, **Refresh**, and the rows: time, kind, target (the host), event, with the counts of an agent entry. It reads `GET /api/logs` when it opens or is selected, on Refresh, when the vault's `rev` changes, and every 2 s while it is the selected tab (the newest 200 entries each time; nothing is read when another tab shows). keel serve logs a host's creation and a trusted key, but not a host's deletion.
- Port forwarding (§5.10). The Port forwarding page: "Each forward opens its own SSH connection. - Settings (§5.9): ⌘,, the footer's gear and the palette open the page. **Appearance**: Theme (System, Light, Dark), Window opacity (30-100), on macOS Window blur (0-64), and UI size (11-16) (the window has no shadow and no setting for one). **Terminal**: Font, Text size (shared with ⌘+ ⌘- ⌘0) with a preview, Copy on select (on by default) and Right-click in the terminal (Paste, Menu, Nothing; Menu by default). **Keyboard**: the keys this client has. **Sharing**: Display name (40 characters, empty uses KEEL_NAME or the user name) and the Signal server (`PUT /api/share/signal`, keel serve validates it; KEEL_SIGNAL and a built-in server show as such). **Vault & security**: State, Unlocked with, the vault file with **Copy path**, nothing secret. **Runtime**: Build, Address, Data folder, Process id, Running sessions, Uptime, and **Stop runtime…**, which asks first (also from the palette's "Stop Keel runtime"). **About Keel**: Version, Build and the two links. A search box reads every row. Window opacity and Window blur apply live to a window that started below 100; Transparent cannot change on an open window, so a window that started opaque saves the value and says it applies from the next start. Crossing 100 paints the grounds opaque and clears the blur; the terminals keep their transparent background and the opaque ground shows through. Text size and Copy on select apply to every pane at once; Right-click in the terminal applies to panes opened afterwards (the terminal takes it when it is made).

### Folders, groups and group runs

Folders, the Group page and group runs (§9, §17). **Folders**: a vault folder is a `Group` with a parent. When keel serve has folders the Hosts section is a nested tree (`HostList`, `treeGroup`): hosts in no folder first, then each folder by name with its host count (everything below it), its hosts and then its subfolders; clicking a folder collapses it. The folder's menu (right-click or "…"): Roles and runbooks, Run a runbook…, New host (the folder picked), New subgroup, Edit, Rename (the name turns into a field: ↵ keeps it, Esc and an empty or unchanged name leave it), Move into… (the same dialog), Delete (asks "Remove group <name>? Hosts and subgroups move up one level."). The sidebar's more-host-actions menu has **New group**. **New group / Edit group** is a dialog (Label, Parent Group, "Save group", the server's own "name is required" and depth words). Drag a host or a folder onto a folder, or onto the tree to take it out of any folder; a folder onto itself or its own descendant is refused with "group cannot nest under itself", and a nest past 8 with "group nest is deeper than 8", before any request. The host menu's **Move to folder…** opens Edit host on its Folder field (which only picks an existing folder). Without folders the flat list of the host's group name stays. The rules are in `folders.go` and `folders_test.go`. The folders the tree shows closed are kept across a restart as `groupCollapsed` in `keel-native.json`.

**The Group page** (palette "Group <name> · roles and runbooks", the folder menu's Roles and runbooks): a tab page, one instance, named after the folder and kept in the saved workspace. The head ("Folder · N hosts · production", **Run a runbook on this group** with the runbooks that have steps, their step count and roles; **Export to Ansible**), the role chips ("3 worker"), the hosts table (host, address, Role, tags, Agent), the group's **Notes for the agent** (the same notes list, kind group: `groupId`, never a host), and **Group variables** (add, edit, remove; a value keel serve refuses as secret-looking or because it holds a vault value is shown in its words and kept nowhere). Roles are saved one host at a time by keel serve (`PUT …/roles`), which checks the word. The **Export to Ansible** drawer shows the files `GET …/ansible` built (INI | YAML, Inventory only or a playbook per runbook, Rolling | Parallel, the two options, the dry-run hint), as keel serve built them: a variable it withheld (its value is also in the vault) is not in them; **Copy** puts the shown file on the clipboard and **Download** saves it where MyGo's save dialog (`mygo.Dialog.Save`, `w.saveDialog`) says, under the file's base name, "Saved <name>." (a cancelled dialog writes nothing; a failure is said). The Runbooks editor has the step fields of §17: a role, **One host only** and captures (name and pattern; "Capture a value").

**Group runs** (`grouprun*.go`): "Run a runbook on this group" starts a run (rolling), whose page is a tab page ("Run · <runbook>", one instance, kept in the saved workspace while keel serve holds the run): the steps with their marks and where each runs (above the detail under 760 px of page width), Rolling | Parallel (off while keel serve says it cannot change), the proposal card (the saved command with its `{{names}}` as chips, "Uses 1 group variable · filled in at Type", Copy leaving the names in), the halt banner (Retry host, Skip host, Stop runbook), the hosts that have no pane open with **Open <host>**, the captured values as a mask and a length, and the Results matrix (✓ exit 0, ✗ exit 1, ◌ running, · waiting for you, – skipped, "exit 0 · confirm", "marked done", "· maybe"; Confirm, Mark done, Retry, Skip). The window asks keel serve every 1.5 s to propose for the panes it has open **and drives** (a followed pane is not named), never while the dialog is open. Stop runbook asks first. Closing a pane does not end the run: the host is listed as having no pane. The approval is "How Keel types for you" below.

### Sharing and joining

Share and Join (§5.6 and §5.7; `docs/sharing.md` for users). **Share**: the title bar's **Share** button (and an "N watching" badge, with the people who came by link) opens the Share popover on the focused session tab, as does the pane menu's Share and the palette's "Share session (join link)". Opening it shares the session (`POST /api/share`) and puts the link on the clipboard; it shows **Live link**, the Join link field with **Copy** (then **Copied**), the scope and the expiry words ("… 24 hours at most … turned away after 2 minutes"), "In this session · N" (you first, then the driver, then by arrival; each with Driving, Owner or Following and how they came: this window, Keel window, joined by link, with the age), **Pass control to <name>** (on each row when there are several), **Take control** or **Ask for control**, and **Stop sharing**. Escape or a click outside closes it. Without a signal server it shows keel serve's own error ("set a signal server in Settings · Sharing to share"). The Join link field shows the whole link; **Copy** and the automatic copy put it on the clipboard, and nowhere else. The key in it is never logged, put in an error, a toast, a pref or the saved workspace, and the types that hold it print without it. A request to watch is a prompt top right (the region "Share requests"): "<name> wants to watch <session>." with **Allow** and **Deny**; only those two buttons answer it (`share.go` `answerJoin`, the one caller of `AdmitShare`, with a test that counts the callers); Escape, a click elsewhere, closing the popover and the two minutes keel serve allows never admit, and the prompt goes when keel serve says the request was resolved. A request for control is a prompt in the same place for whoever drives or owns the session: "<name> asks for control" with **Hand over** (`grant-control` to that person) and **Keep driving** (sends nothing).

**Join**: ⌘J, the New tab page's **Join session**, the sidebar's "More host actions" menu and the palette open "Join a session"; the field takes the link, and errors are toasts ("paste a Share link", "paste the full Share link", "link has no room", "link has no key (#k=…): ask the host for a new Share link"). The joined tab has a link icon and `<session> · joined`, a haze banner ("Following <owner>'s session on <host> · read-only" with **Ask for control** and **Leave**; "Driving … · you have control" after a hand-over; "Joining a shared session · waiting for the host" before the host lets it in), and in the pane bar "<driver> is driving" and "You follow". It is a terminal and nothing else: no Vault sidebar and no sidebar toggle (⌘B does nothing), no Share, no snippet typed into it (a snippet says "Open a session first"), no split ("Split needs a local host session"), and it is not saved in the workspace or in the recently closed list; closing it (Leave) closes the peer and kills nothing. A failed join (the host declined, the host could not be verified, the connection was lost) shows the message in a flare banner with **Leave** and a toast, and the terminal stays blank; pasting the same link again joins again, and pasting one that is open shows its tab. The peer is `internal/native/joinpeer` (pion, no cgo): `ParseLink`, the verification of the host's DTLS fingerprints with the key in the link (`internal/sharelink`: `MAC`, `CheckMAC`; the key is used for nothing else), and the peer itself. A peer dials the signal server in the link and the one STUN server Keel uses (`sharelink` holds it), nothing else; the tests give it no ICE server. Its `Write` sends nothing unless the host has said this client drives. **What a joined tab cannot do**: type before a hand-over, take Approve before type, split, share, show the vault, be saved, or change the host's session id.

### The agent

The agent panel (§5.4; `docs/agent.md` for users). A 380 px panel on the right (`size-agent`, at least that wide and at most half the window; the sash on its left edge widens it by dragging left, ← → step it by `size-agent-step` and ⇧ four times that, Home goes back to the narrowest, a double click puts the default back; the width is kept as `agentWidth` in `keel-native.json`), one per window, toggled with ⌘I (Ctrl+⇧I off macOS), the title bar's **Agent** button with its key cap, the palette's **Toggle agent panel** and the Keyboard page's row; open or closed is kept as `agentPanel`. **Ask**: the header has the conversation's title ("New conversation" until keel serve names it), **New conversation** and **Close agent**; the scope chip "Reads N of M panes" opens "Panes the agent reads" (a row per terminal pane of a local tab, the host's Production badge, "Agent can't read" on a host with reading off, which cannot be picked and is dropped from the scope when reading is turned off; the presets Focused pane, Every pane in tab and None); a new conversation starts from the agent setting `defaultScope`. The composer takes ↵ to send and ⇧↵ for a newline, `@` at the start of a word opens the picker and is not typed, a chip per pane in scope has × (the "Stop reading <host>" button), **Stop** cancels the ask, and the foot says "Nothing reaches a pane until you press Type. The agent cannot type into panes you follow, and never sees the vault." An ask is `POST /api/agent/ask` with the conversation id, the question and the session ids in scope, and nothing else: keel serve reads the panes, redacts them and asks the model, so this client reads no scrollback for the agent (`TestNoFileReadsPaneTextForTheAgent`). Every ask writes one `agent.read` entry to `keel.log`, also with no pane in scope; when `keel.log` cannot be written keel serve refuses the read, the send and any approved Type until it can, and the window shows its reason as the error block. The answer comes back in one piece (it is not streamed), `keelclient.Ask`, and Stop cancels its context.

**Thread**: your words, the trace ("Read <host> · last <n> lines · <k> redacted", "last command, exit 1", "Skipped <host> · the agent can't read this host", "Read no pane", "Test provider · nothing left this machine"), the answer (paragraphs, `code`, **bold** and fenced code blocks with Copy, drawn as text: no link is opened and no image fetched), the cut-off notice, and the error block ("No model is connected.", "The vault is locked.", "The agent could not answer." with keel serve's reason). **Proposal card**: "Run on <host>", the Production badge, Read-only / Changes state / Destructive, the exact bytes (^U, the command, ↵), the why, "1 line · 20 bytes", **Edit** (a field and **Save command**: `PUT /api/agent/conversations/{id}/proposals/{pid}`; the card and the dialog then show what keel serve answers, never the field), **Copy** (the command, not the bytes) and **Type into pane…**, and the card's right-click menu with the same actions. Destructive, or a state change on a production host: a plain Type is refused in the card ("Not typed. Destructive: hold ⇧ and press Type."), and ⇧ held on the click opens the dialog with ⇧ for keel serve's check. A pane you follow, a closed pane, a proposal with no pane, an expired proposal and one that holds a redacted placeholder get no Type button, with a note. After a Type the card says "Typed into <host>." or keel serve's refusal; Cancel leaves it as it was. A read-only one-line proposal that keel serve agrees to is typed without the dialog (§6 rule 13): the card's button says **Type into pane** (no ellipsis) when the window expects that and **Type into pane…** when a dialog will follow, a destructive, state-changing or production ⇧ proposal never goes direct, and the card says "Typed into <host>. Press Enter to run." or keel serve's own words. **No key**: the inline "Connect Gemini" card with the provider's words and warning, the terms link, and the masked "Gemini API key" field; Connect sends the key once (`PUT /api/agent/keys/{provider}`) and the field is emptied as it is sent, so a refused key is typed again. A joined tab has no panel and no button, and ⌘I says "The agent is off in joined sessions". The window never calls `keel mcp`'s routes (Claude Code is switched in Settings · Agent only).

**Saved conversations and the Agent page** (§5.4.1, §5.4.2). The panel's title is a button (with a chevron) that opens a list under the header: a search (title or host), the Today / Yesterday / Older groups with counts, a row per conversation (title, up to three host badges, the time, "· N proposals"), **Rename** (an inline field: ↵ saves, Esc leaves the title) and **Delete** on each row, the retention note ("Kept 30 days", "Kept 1 year", "History is off"), **Open all in a tab** and **Delete all**, with ↑↓ to move and ↵ to open the row. The sub row says "Saved in the vault" or "Not saved · kept while open" (history off), or "Not saved" when keel serve could not save. **New conversation** keeps the old one in the list. **Resume** reads the transcript (`GET /api/agent/conversations/{id}`) into memory and shows the saved thread, the "Resumed · 3 hours ago" divider and the note under it; the next ask carries the saved conversation's id. **Expired proposals** (keel serve no longer holds them): the card has **Copy** and **Propose again** and nothing else: no Type, no Edit, no card menu, and `typeAgentProposal`, `startEdit` and `editAgentProposal` refuse an expired one a second time. Propose again (`POST …/proposals/{pid}/again`) adds a live card that goes the usual way; the new proposal names a pane only while the old pane is still open on the same host, so after a daemon restart it is Copy only. **Delete** on a row or on the page deletes at once and says "Conversation deleted"; **Delete all** asks first ("Delete all conversations?"). Conversation text lives in memory only: nothing of it is written to `keel-native.json` or the saved workspace (`TestAConversationIsNeverWrittenToDisk`). **The Agent page** (a tab, one instance, "Agent conversations" in the palette or **Open all in a tab**; ⌘N is New conversation): the list (search, the host chips All and up to six hosts, the groups, "Saved encrypted in the vault · kept 30 days" and **Retention settings**, which opens Settings · Agent), the conversation (title heading with **Rename** and **Delete**, the meta line, **Continue in panel** ⌘I, the same thread and cards as the panel, whose Type names its pane with its tab, and a composer), and the context column (In scope, Read so far, Proposals, and "Every read and every typed proposal is also in Logs, under Agent."). The page shows the window's one conversation, so the panel and the page never disagree; below 960 px of tab width the context goes under the list, below 660 px the two columns share the width 2:3.

**Settings · Agent** is the section after Keyboard: the provider cards (Connected / Not connected, **Change key**, **Disconnect** which asks first, the masked key field that is emptied as it is sent, the provider's warning and links), Model, the Suggestions in panes switches and detection radios, the default panes, Scrollback lines per pane (50–1000, steps of 10), **Allow Claude Code (keel mcp)** (off by default; only `claudeCode` is sent), the Safety rows, Keep conversations and **Delete all history** (asks first), and "Notes for the agent" (Your notes, Delete all notes). Every change is saved as it is made with `PUT /api/agent/settings` and only the fields that changed (keel serve merges them), and the answer is what the screen shows (`agentsettings.go`).

**Notes for the agent and runbooks** (§15, §16). Both live in keel serve (`keel.memory` in the vault), which cleans, redacts and logs every save (`agent.note`, `agent.runbook`); this window holds them in memory only and writes none of their text anywhere (`TestNotesAndRunbooksAreNeverWrittenToDisk`). **Never saved by the agent**: a note or a runbook it proposes is a card, kept only by that card's Save (`POST …/notes/{nid}`, `POST …/runbooks/{rid}`), which one function sends and only the Save button calls (`TestAProposalIsKeptOnlyByItsCardsSaveButton`); Dismiss keeps nothing; no timer, load, ask or retry saves. **Notes**: Edit host has the "Notes for the agent" list (the count "1 note · 40 chars", each note with where it came from, Edit and Delete, the field "Add a note" where ↵ adds without submitting the host form, "Agent can read is off, so these notes are not sent. The thread has the **"Remember this?" card** (the text, "Host notes · api-1" or "Your notes · every host", when it is sent, where it was seen, "From pane output" or "After reading panes" with warnings, Save or **Save anyway** when a pane was read, Edit, Dismiss, then "Saved to host notes · api-1" with **Undo**) and the trace row "Used host notes · api-1 (2)". **Runbooks**: the **Runbooks page** (tab, from the palette's Runbooks; ⌘N is its New, ⌘S saves) has the list (filter, source badge, Use when, hosts, the "Agent may pick" switch, "N runbooks · stored in the vault"), the editor (name, Use when, steps with title, description, command and expected result, move up and down, remove, Add step, "Agent may pick this runbook", hosts as chips, Source, Last used, Steps), the review banner "Not enabled yet. The thread has the **"Save as a runbook?" card** (saved with Agent may pick off, "Open Runbooks", Undo) and the **run card** under "Agent": the runbook, "Run on <host> · <tab>", why it was picked, the steps with ✓ – ✗ and their notes ("exit 0 · reported"), what to do now (**Propose step N**, Mark done, Skip, Retry, **Confirm done** after a reported exit 0, Move the run to another host), **Use a different runbook** (a runbook that does not fit the panes in scope says why), **Don't use**. **A step is an ordinary proposal**: Propose step N is an ordinary ask (`Continue with step 2 of 3: …`), keel serve makes the proposal for the current step only ("Step 2 · Run on"), and its card is typed by `typeAgentProposal` and nothing else; this window builds no step's bytes, knows none, and asks about no step but the current one (`TestNoteAndRunbookCodeHasNoWriterAndNoWayToType`, `TestARunbookStepIsNeverBuiltAsAProposalByTheClient`). A typed step's result is read from keel serve while it waits (every 1.5 s, at most 10 minutes). A proposal that holds a redaction placeholder gets no Type button; keel serve refuses to keep a runbook step that holds one, from the API and from the editor, so a saved runbook never makes one.

### Notebooks

A notebook is one Markdown document kept by keel serve (§18); this window holds the list and the open text in memory and writes no text anywhere (the workspace file keeps a notebook pane's id and place only: `TestANotebookPaneComesBackWithTheWorkspaceAndTheFileHoldsNoText`). **Sidebar**: the Snippets segment has a **Notebooks** section under the snippets (a row per notebook, pinned first then newest then name, the pin button, the row menu, "No notebooks yet." / "No notebooks match.", **New notebook**, **All notebooks**), under the segment's one filter. **The Notebooks page** (a tab; palette **Notebooks**; ⌘N is New notebook): **Recently deleted**, **New notebook**, **Filter notebooks**, rows with the first line and the badges Private, Edited by agent, From agent and Pinned. **Row menu**: Open, Rename (a dialog; `PATCH` with the name alone, so a window with an old copy never writes old text back), Pin or Unpin, Make private or Let the agent read it, History, Delete (asks; when keel serve cannot keep it in Recently deleted it asks again, "Delete it permanently?", and retries with `?permanent=1`). **Palette**: Notebooks, New notebook, Split notebook, "Open notebook <name>". **The pane**: opened from a session tab it is a split beside the terminal, otherwise a tab of its own named after the notebook (opened again, it takes the open one); the bar says "Notebook" with the same split, focus view, more and close; then the review banner of an agent edit ("Written by the agent" or "Edited by the agent · <when>" and **Mark reviewed**), the title field (a change saves with the text), the meta line (Notebook · Updated <Mon D> · the host chip of the terminal fences type into, or "No terminal in this tab" · Private or "Agent can read" · History · the "Edited by agent" badge · **Edit**), a rule and the document. The notebook pane that had the keyboard (or was in focus view) comes back so, by its id (`focusedNotebookId` and `zoomedNotebookId` of the saved tab). The tab strip names a tab of notebooks after the one in front and gives it the notebook glyph where a session has its state dot.

**Read and edit.** The notebook is read rendered and edited as Markdown source. MyGo's rich text editor cannot hold a notebook safely (it merges adjacent code fences into one command block and rewrites the stored Markdown on save: tables, rules, HTML, hard breaks, callouts, lists), so the document is MyGo's Markdown view (links open only through `ui.SafeToOpen`: http, https, mailto; images show as their descriptions, since the window never fetches from the network; raw HTML shows as text) and **Edit** is a plain text area on the stored text, which is never passed through a rich text model. There are no input rules while typing (`# `, `- `, ` ```sh `, smart quotes), no keymap (⌘B, ⌘I), no language picker in the fence bar (the language is the one the fence names), no callout box for a quote, and the caret is not carried between modes. **Edit**, a double click on the document, or a new, empty or very long notebook shows the Markdown as plain text in the mono font; **Done**, Esc or ⌘↵ shows it rendered again. A notebook over 64 KiB opens in Edit, not rendered: MyGo's Markdown view lays out every block and took about 6 s for 256 KiB (about 1.5 s for 64 KiB) while the text area types in about 1 ms (`TestAHugeDocumentIsUsableInTheTextArea`). The text is saved as typed (no trim, no rewrite): autosave 1 s after the last edit and at least every 5 s while typing goes on, one save at a time (`autosave`), flushed on Done, on closing the pane or the tab, before a fence is typed and when the window closes. A save sends the revision the pane loaded; "Saved your typing over an agent edit this pane had not loaded. The agent's version is in History." when keel serve says so; a notebook that changes on the server while the pane has unsaved typing keeps the typing and says so once when the agent made the change ("The agent edited a notebook you are typing in…"), and one with no unsaved typing shows the new text; a failed save says "Could not save notebook" (or keel serve's reason) and the text stays.

**Fences** (`fences`, parsed with `github.com/egoist/mygo/ui/markdown/parser`, the Markdown the server stores): each fenced block, in a quote or a list item too, has a bar with its language, **Copy code** (exactly the code, toast "Copied") and, for a `sh`, `bash` or `shell` fence, **Type into <pane>** ("Shows the command for <pane> first. Nothing is typed until you confirm."), or **Type into pane** with no terminal beside the notebook: pressing it then says "Split a terminal beside this notebook first" and sends nothing. Two fences next to each other are two blocks with their own buttons. **Typing a fence is the snippet's two paths and no third**: a one-line fence with no `[secret:1]`-like placeholder goes through `typeNow` (the notebook is saved first, the frame carries `kind: notebook` and the notebook's id, keel serve compares the line with the stored fence, refuses an unreviewed agent edit with a dialog, types the line with no Enter and no Ctrl-U, and the toast says "Typed into <pane>. Press Enter to run."); everything else, and whenever keel serve says a dialog is needed, is Approve before type with the fence's exact bytes: the trimmed code and a newline, **no Ctrl-U** (the fence's text is appended to whatever is on the prompt line and the newline runs it; the notebook's dialog drops the sentence "The current line is cleared first." from its hint for that reason, `TestTheNotebookDialogDoesNotSayTheLineIsClearedAndASnippetsStillDoes`), and the inject carries `notebook: true` (keel serve refuses a placeholder then; the client refuses it first, and a refusal that still arrives stays in the dialog). A notebook with an unreviewed agent edit puts a note under the bytes. A followed pane cannot be typed into; the dialog says so. No writer was added for notebooks: `ApprovedInject`, `DirectType`, `SuggestInsert` and `RestoreWords` have the call sites they have elsewhere (`TestNotebookCodeHasNoWriterAndNoCallSiteOfItsOwn`, `TestTheNotebookInjectFieldIsWrittenOnlyByInjectGo`). Opening, rendering, editing, saving, restoring and deleting type nothing.

**History and Recently deleted** are one dialog (`notebookdialogs.go`): the versions (who, what, when, the agent's summary), the lines that changed "From this version to now: N lines added · M removed" with two lines of context and gaps, **Restore this version** (saves first, posts the rev; "Restored. The version it replaced is in History."), **Delete this version** (asks); and for deleted notebooks the text, **Restore notebook** ("Restored “X” to Notebooks.") and **Delete forever** (asks), with "Nothing was deleted in the last 30 days." when empty. A time in History is "just now", "N min ago", "today 14:05" or "Oct 19 14:05" in the system's regional formats (day and month order, month names, 12 or 24 hours: `clock.go` reads `mygo.App.Region()` and writes with `i18n.FormatDate`); the same goes for the conversation lists, the notes' days, the Logs times, the key dates and the group run's times. Only the numbers and month names follow the region; words such as "today" stay English.

**Notebooks and the agent** (§18, §6 rule 12). keel serve decides everything here; the client sends ids, shows what keel serve answers and posts the user's click. **Attach notebook** (the button in the composer of the panel and of the Agent page): a picker "Notebooks to send with your question" lists every saved notebook (pinned first, then by name), at most two ticked, a private one listed with its Private badge and never tickable (a click says why: "This notebook is private: the agent cannot read it. Turn Private off on the notebook first."; a third says "Attach at most 2 notebooks to a question"); ↑ ↓ walk between rows (wrapping), Escape closes it. A ticked notebook is a chip with **Stop sending <name>** and the line "This notebook is sent, redacted, with each question until you remove it." (or "These notebooks are…"); the ids are reconciled every frame, so a notebook deleted or made private drops off. An ask names the attached notebooks by **id and never by text** (`AskRequest.Notebooks`), and the notebooks open here with typing not saved yet (`Editing`: a save pending, running or failed), after saving what can be saved first; keel serve then refuses the agent's edit to those. **Ask the agent about this notebook**: the row menu of the sidebar and the page (not for a private notebook) and the notebook pane bar's first tool (not for a private one; an unsaved notebook says "Save the notebook first, then ask the agent about it"): the panel opens with the notebook attached and nothing is sent. **Trace lines** (`notebookStepText`): "Sent the titles of N notebooks (not private)", "Sent notebook <name> (N bytes, cut by Keel, M redacted)", "Read notebook <name> (…) · the agent asked", "Skipped a notebook · it was deleted", "Not sent · a private notebook (the agent cannot read it)", "Stopped reading notebooks · Keel's limit for one question". **The cards** (`agentNbCard`, after the proposals, notes and runbooks): the head (Created notebook, Edited notebook, Notebook not created, Notebook not changed, Delete notebook?, Delete notebook, Notebook draft), the badges (From agent, Edited by agent, From pane output or After reading panes, Placeholders), the title, the status line, the summary ("Why: " for a delete), the pane warning when a pane was read, "N bytes · rev R", and the buttons of `cardActions`, named with the notebook's title ("Undo Ops") so several cards tell apart: **Open** (the notebook as the Notebooks page opens one), **Undo**, **Restore**, **Keep** and **Delete…**. Each of Undo, Keep and Restore is one request (`POST …/notebooks/{nid}/undo`, `DELETE …/notebooks/{nid}`, `POST …/restore`); **Delete…** asks first ("Delete the notebook “X”? The agent asked for this. It goes to Notebooks · Recently deleted, where you can restore it for 30 days.") and only the confirm's **Delete** posts `…/delete`; Cancel posts nothing. After a request the card shows the proposal keel serve answered and the notebook it returned goes into the list and into an open pane that has no typing; Undo of a created notebook and a confirmed delete close the notebook's pane. A card has the right-click menu of its own buttons. An expired card offers only Open and says "Keel no longer holds this conversation's changes. Use History on the notebook to see or restore a version."; a draft from an older Keel shows its text and has no Save. Saved conversations and the Agent page show the cards. **An agent edit of an open notebook**: with no unsaved typing the pane shows the new text and the review banner; with typing the pane keeps it and says so once, and when the ask named it keel serve refused the edit ("You were typing in it, so Keel did not apply the agent's edit."). **The review banner** has **View changes** (History with the version before the agent's edit selected), **Undo** (restores that version at the revision the window has; it asks first when the user changed the notebook after the agent; "Keel has no version from before the agent's edit. Open History to choose one." when there is none) and **Mark reviewed**, the only thing that clears the mark; it wraps in a narrow pane. **From a notebook…** on the Runbooks page lists the notebooks (private ones too) and makes an unsaved draft with one request (`POST /api/agent/runbooks/draft` with `{notebookId}`): headings become steps and shell fences their commands, nothing is kept until Save in the editor, the draft starts with Agent may pick off and says when the notebook is private; a 422 is the toast "Nothing to make steps from: no headings or shell blocks, or no proposals." The fake provider keeps its record of what it was given in the daemon's memory and does not expose it, so `TestE2EAgentNeverSeesAPrivateNotebook` proves a private notebook never reaches the agent by what the fake said, the trace, the cards, the window's text and the log; the service's own test (`TestPrivateNotebookNeverReachesTheAgent`, `internal/agent/service/notebooks_test.go`) reads the request itself.

### In-pane suggestions

**Suggestions start only when you ask.** The default detection is "Only lines starting with `#`": a line you start with `#` is a request (after a 350 ms typing pause it is highlighted with the hint "Looks like a request · ⇥ suggest a command", and ⇥ asks), and **Suggest a command for this line** asks for whatever is on the prompt line now, with any words and no `#`: ⌘Y (Ctrl+⇧Y off macOS, since Ctrl+Y is the shell's yank), the palette's action of the same name, listed on the Keyboard page. ⌘Y is no macOS system shortcut and is not sent to the shell. The key only asks (the pane's one question to keel serve, `agent-suggest`); it types nothing, and the card's ⇥ / ⇧⇥ is still the only way a command is inserted. keel serve logs the request as it logs a ⇥ request (`agent.suggest`). **What a typed line sends**: with suggestions off nothing; with "Only lines starting with #" nothing for a line without `#` (no frame at all), the `#` line for its notice, and the line on ⌘Y; with "Notice automatically" (opt in, needs a Jev key) every line of two or more words after the pause, which keel serve's Jev judges, and ⌘Y; in every mode ⌘Y sends the line once. In "Notice automatically" a noticed line shows the hint "Looks like a request · ⌘Y suggest a command" and **does not take ⇥**, which stays the shell's (a `#` line's notice takes ⇥). Turning suggestions off, or changing how a line is noticed, acts in every pane at once: from this window's Settings · Agent or First run, and through the vault `rev` poll when another window changed it, each pane drops its cache of plain lines, a pending check, the notice and (when off) a loading request or a card, sends nothing more while off, and ⌘Y then says "Suggestions in panes are off. Turn them on in Settings · Agent." A request is never left loading: keel serve answers every `agent-suggest` it accepted (a card, or an error including its own 30 s model timeout; only a request replaced by a newer one from the same pane is silent), and the window gives up after 37 s with "No suggestion came back." and ⇥ / esc to dismiss it. A settings file that holds detection "auto" from before this default is moved once to "hash-only" on load (`agentDetectionDefault` in `keel.json` records it); "auto" chosen afterwards stays.

**How it looks and works**: ⇥ (on a `#` line's notice) or ⌘Y shows "Suggesting a command…" (`loading.Blocks`, below) and then the card under the line (above it when it does not fit): where the command came from ("Suggested from your words", "From this pane's scrollback", "From your snippets"), the risk badge (Read-only, Changes state, Destructive or "Deletes files"), the command, the reason, the redaction note, the other options (1-9 and ↑ ↓ pick, a click picks), the foot "⇥ insert · ↑↓ other options · esc keep my words", the red edge and "⇧⇥ insert anyway" with "Plain ⇥ never inserts a destructive command" (or "Production host: ⇥ alone does not insert a state change"), "Press ⇧⇥ to insert this command." on a plain ⇥ that needs ⇧, and a later, stricter rating from Jev (never a looser one); ⇥ / ⇧⇥ inserts in place of the words, never run; "Inserted, not run · ↵ run · ⌘Z back to your words"; esc keeps the words and ⇥ is the shell's again; a refusal keeps the card with keel serve's words. No notice, card or frame for a follower, a joined pane, a session that is not ready, a pane in the background, a dialog over the pane, or a full-screen program. The put-back key is on the Keyboard page. **Held by**: `suggest_test.go`, `suggestpane_test.go`, `keelclient/suggest_test.go`, `suggestgate_test.go` (the three facts the terminal plugin must give: the prompt line from the Snapshot, `Options.OnKey` taking keys only while the window says so, and a cell's rect measured from the font that equals the plugin's own caret rect at two display scales, after a resize and a text size change) and `e2e_suggest_test.go`. **Known differences**: a line that wraps onto a second row is not noticed (the Snapshot does not say which rows are soft wraps; the page joins up to 9); wide characters count as one cell; typing is seen through `OnKey`, so on a platform where the plugin delivers a typed key as text alone (Linux) the typing pause does not start until a key it does see; the hint wraps to the row below by an estimated width; the card has no entry animation; the line is read at most every 100 ms while a notice or card shows (the Snapshot holds the scrollback); esc on the notice removes it and is not sent to the shell, while esc with no notice or card still goes to the shell.

## How Keel types for you

Keystrokes from the terminal view are the only thing that reaches a session unasked (with Sync input on, the same keys also reach the other terminals of the tab: the fifth writer, below). Everything else Keel types goes one of the ways below, all written by one file, `keelclient/inject.go`, which is the only code that builds an `inject-challenge` or an `inject` frame (a text frame the server answers with a one-time nonce, then the same bytes with that nonce), and each way has one caller. keel serve has no `type-check` question any more: whether a direct type is allowed is decided at the write, and `guard_test.go` fails if a file names `DirectCheck` or `type-check`.

**Approve before type** (the dialog): `(*keelclient.Conn).ApprovedInject`, whose only caller is the dialog's Type action (`approve.go`). keel serve writes exactly the bytes it is given for a nonce it issued for those bytes to the driver (`internal/runtime/runtime.go` InjectTicket) and adds nothing, so the client builds them: the command gets a trailing newline if it has none, the dialog shows that text, and what is sent is Ctrl-U (it clears the line first, as the dialog says) followed by exactly that text. The dialog has the title "Type into the terminal?", its sentence, "Session:", the text in the mono font as it is, Cancel and Type; the keyboard starts on Cancel. Opening it, Escape, Cancel and a click outside send nothing; no nonce is requested before Type; the preview is asked for again every frame and when Type is pressed. Type is off when this client is following ("You are following — take or request control to type") or the session is not ready ("Session is not connected"); a missing nonce (keel serve says nothing to a bad request) ends after 2.5 s with "Session is not connected" and nothing is typed, and Keel never retries. Snippets have no production or ⇧ rule (it lives in agent proposals).

**One-click type** (§6 rule 13): `(*keelclient.Conn).DirectType`, whose only caller is `(*workspace).typeNow` (`typenow.go`), which every entry point goes through (a snippet from the palette, the sidebar, the page or its row menu; an agent proposal's card; a notebook fence). The command is typed with **no dialog and no Enter**, and it is appended to whatever is on the prompt line; nothing runs until the user presses Enter in that pane. **keel serve decides, every time** (`internal/httpapi/typedirect.go`): it takes the command only if the client drives, the pane is not a share peer's, the pane is at its shell's prompt and not on the alternate screen, the last line does not ask for input, the command is one line with no control or invisible character and matches an exact read-only grammar (`cmdrule.DirectSafe`: `pwd`, `df -h`, `ls [-l|-la|-lah] [PATH]`, `kubectl get RESOURCE [-n NAME|-A] [-o wide]`, `systemctl status UNIT --no-pager`, and a few more), the bytes are the snippet's or the proposal's own, and (with a Jev key) Jev rates it read-only; otherwise it answers "dialog" and nothing is written. The client only skips the round trip when the answer is certainly "dialog" (`directHint`, which applies the same `cmdrule` rules). A direct type carries a fresh nonce for exactly the command, and the pane's state with it: `altScreen` and `promptLine`, read from the terminal's `Snapshot` (the plugin has no call for either; `screenOf` reads the modes 47, 1047 and 1049 and the cursor's line from it, and a terminal that cannot say is sent as the alternate screen, never as a prompt). The bytes are the command alone: no Ctrl-U, no newline (`DirectType` refuses any control or invisible character before it sends a frame, and the server refuses it too); the client never sends an Enter. One at a time per pane ("Still typing the last command into this pane."), never queued; no answer in 8 s shows "keel serve did not answer. Check the pane before you press Type again." and opens **no** dialog and does not retry (it may have been typed). After a direct type the note "Typed into <pane>. Press Enter to run." shows and the terminal gets the keyboard once no key is held (a held ↵ that pressed the button must not repeat into the pane). `guard_test.go` fails if another file builds one of the frames, if `ApprovedInject` or `DirectType` has another caller, if `typeNow` is called from anywhere but the snippet and card entry points, if a file other than `approve.go` and `typenow.go` builds an `AgentRef`, if a direct type's code adds a control character, or if `Write` is called on a connection outside the terminal view's own wrapper (`syncinput.go`).

**An agent proposal** is typed through the dialog and the same function: `ApprovedInject` takes an optional `AgentRef` (conversation id, proposal id, ⇧) which it adds to the inject frame and only there (the `inject-challenge` carries the bytes alone), keel serve checks the proposal against what it holds (the exact bytes, the pane, the role, the ⇧ rule) and logs `agent.type` before it writes (refusing when `keel.log` cannot be written), and answers with an `agent-type` frame that the call waits for (4 s, then "keel serve did not answer."); a refusal comes back with keel serve's own words, types nothing and is never retried. The bytes are the proposal's `bytes` as keel serve built them (`internal/agent/service/format.go` typedBytes: Ctrl-U, the command, a newline), so the dialog adds neither: it sends them as they are, and shows them with the control characters as glyphs (^U, ↵), as the card does. `guard_test.go` also fails if the agent keys of the frame appear outside `inject.go`, if a file other than `approve.go` builds an `AgentRef`, or if any file names a scrollback or `/api/mcp` route.

**A suggestion's ⇥ / ⇧⇥** (§5.5) is the third way, and it has the same shape: `(*keelclient.Conn).SuggestInsert` in `inject.go`, whose only caller is `(*workspace).insertSuggestion` (`suggestpane.go`), reached only from the machine's insert when a card is open and ⇥ or ⇧⇥ is pressed. It sends an `inject-challenge` for the bytes **keel serve itself gave for that option** (`agent-suggest`'s `bytes`: Ctrl-U and the command, no newline, kept inside `keelclient` and never handed to the window), then the `inject` with the nonce and `suggestion: {suggestionId, option, shift}`; the caller names the suggestion, the option and ⇧ as the key was pressed and cannot name bytes, and `shift` is never upgraded. keel serve (`AuthorizeInsert`) checks the suggestion, the bytes, the ⇧ rule and that this client drives, logs `agent.insert`, writes, and answers `agent-insert`; a refusal comes back in its words and is never retried. An insert never ends with Enter (a line with a newline in it is refused here: "This command spans lines; copy it instead."), so the command waits on the prompt line for the user's own Enter; the window re-reads the prompt line right before the write and drops the card, writing nothing, if the words changed. ⌘Z right after an insert (Ctrl+Shift+Z off macOS) puts the user's words back as their own keystrokes: `(*keelclient.Conn).RestoreWords` (Ctrl-U and the words with every control character dropped), whose only caller is `(*workspace).restoreWords`. The two questions (`agent-detect`, `agent-suggest`) write nothing and are asked only by `suggestpane.go`. `guard_test.go` holds each of these: the frames only in `inject.go`, one caller each for `SuggestInsert` and `RestoreWords`, no `SuggestionRef` built outside `suggestpane.go`, and no Enter in the suggestion code.

**A group run's step** (§6 rules 10 and 11, §17) is typed through the same dialog and the same writer: "Type into N panes" on the run page opens the **group approve dialog**, which shows the exact bytes once (with their line and byte count) and one row per host (name, the pane's tab, Production and ⇧ badges). **No row is ticked in advance** unless there is only one host; only ticked rows are typed; a pane this window follows or has closed is not offered, and a row whose pane closes or becomes a followed one while the dialog is open says so and is not counted. The dialog's Type is the same `approveType` and the same single `ApprovedInject` call, made once per ticked row inside one loop in that function: each ticked host is its own `AgentRef{GroupRunID, ProposalID, Shift}` (the proposal keel serve made for that host from the saved step), sent on **that pane's own connection**, so each gets its own server nonce for exactly its own bytes and keel serve authorizes each on its own (`AuthorizeType`: the bytes, no placeholder, the host still in the group and readable, the ⇧ rule with that host's production flag now, the driver). A row that needs ⇧ is typed only when ⇧ was held with Type (otherwise nothing at all is typed and the dialog says to hold it). A refusal for one host is that row's own ("Typed." or keel serve's words on the row, a toast naming the hosts) and does not stop the others; the dialog then stays so each row can be read, and a reached row is final: nothing is retried. A step that names variables (`{{name}}`) is stored, shown on the run page, and logged with the **names only**: "Type into N panes" first asks keel serve to fill each host's proposal (`POST …/fill`, which writes nothing), the dialog shows those exact bytes (once when every host gets the same, else per host, with where each value came from), and what is typed is those bytes unchanged; keel serve fills again at Type and refuses other bytes. A host whose fill failed shows why and cannot be ticked. The client never builds, edits or substitutes into the bytes of a row (`guard_test.go` checks it). The window does not type a read-only group step with one click and no dialog (§6 rule 13 is still marked "for review, not yet accepted" in the spec): every group step goes through the dialog. `guard_test.go` also fails if `GroupRunID` or the key `groupRunId` appears outside `inject.go` and `approve.go`, if the loop leaves `approveType`, if a row is ticked by anything but the user's click on its check box (or the one-host case), if a group file names a writer, or if a row's bytes are set anywhere but from keel serve's answer.

**The fifth writer: Sync input** is the user's own keys, not something Keel types, and it is the only code besides `keelclient` and `joinpeer` that calls `Write` on a session. The terminal view is given `newSyncConn(p)` (`syncinput.go`, called once, from `liveBodyT` in `run.go`) instead of the bare connection. Its `Write` sends what the terminal writes (the user's keys and paste, and the terminal's own protocol replies to a program's queries) to the pane's own connection and, only while the pane's tab has sync on, the same bytes to every other pane of that tab that is a terminal (not a notebook), in a local tab (not a joined one), driven by this client (not followed) and ready; a failed write to another pane does not fail the user's own and is not retried. It runs on the terminal's input goroutine, not the UI thread, so the UI thread publishes each pane's peer list behind a mutex (`publishSync`, every frame and on every change), and readiness and role are read from each connection's own `Snapshot`. It is **never** reached from `approveType`, `typeNow`, a suggestion's insert, `RestoreWords`, a notebook, a group run or the agent: a direct type, an approved inject, an insert and the ⌘Z put-back each go to their one pane, and the suggestion machine sees the typed pane's input only. `TestSyncInputIsTheOnlyFanOutAndNothingTypedReachesIt` (`guard_test.go`) fails if another file calls `Write`, if `newSyncConn` or a `syncConn` is made anywhere but `run.go`, if a file but `syncinput.go` names the fan-out (`fanOut`), if the fan-out is called from anywhere but the wrapper's `Write`, or if `syncinput.go` names `ApprovedInject`, `DirectType`, `SuggestInsert`, `RestoreWords`, `AgentRef`, `typeNow`, `approveType` or `openApprove`.

## Look

The window is **native first**. Three parts: what is MyGo's, what is kept custom and why, and what only a person can check. The numbers that are Keel's own are in `internal/native/nativeonly.go`, with the reason beside each; the brand rules are in `docs/design/README.md`.

### MyGo's

- **Components.** Buttons (`ctlButton`, `controls.go`: `ui.Button` / `ui.PrimaryButton` with the quiet and destructive looks MyGo has no variant for), icon buttons (`ctlIconButton`, with a tooltip of the control's name), text inputs, search fields (`searchField`: `ui.SearchField`), the section switch and the Settings choices (`ui.Segmented`), the host picker's button, switches and sliders. Controls take MyGo's radius, spacing, sizes and focus ring. The conversations filter is a `ui.TextInput` that asks to be a search field (`OnTextKey` does not reach the input inside a `SearchField`).
- **The theme** is built in one place (`windowTheme`, `theme.go`) from MyGo's `LightTheme` / `DarkTheme`. What changed: the accent family, Danger / Warning / Success (flare, signal, tide, so MyGo's components agree with the badges), the control fills at the control alpha, and the font size (13 at the default UI size, scaled by Appearance · UI size). The palette's chrome, text and lines are MyGo's values (`TestPaletteIsMyGos`); the stage behind terminals stays Keel's so it matches the terminal.
- **Font.** All UI text is the system font. JetBrains Mono (and the Plex option of Settings · Terminal) is for the terminal, code and commands, exact bytes, host addresses and key caps.
- **Accent.** The system accent colour: MyGo reads it (`NSColor.controlAccentColor` on macOS, the settings portal on Linux) and a frame gets it as `Context.Preferences().Accent`; zero falls back to MyGo's accent. `deriveAccent` builds the family: the text on the accent is white on a fill darkened by at most a fifth, else near-black, 4.5:1 either way; the accent as text on the page is darkened or lightened to 4.5:1 on the page and the bars (`TestAccentDerivationKeepsContrast`: the eight macOS accents and graphite, both appearances). The family in the code is `accentFill`, `accentInk`, `accentSoft`, `accentStrong`, `onAccent`. Keel's brass is the app icon only: the terminal's cursor is its text colour (`termFg`) with the terminal's background under a block cursor's text, and its selection is the accent's (`terminalColors` in `theme.go`: `accentSet.selection`, alpha 0.4 dark, 0.25 light). In a find, other matches are a neutral tint (the background mixed 30% toward the foreground, text in the foreground) and the current one is the accent. A new system accent while running gives every terminal the new selection (`resolveTheme` compares the accent family and calls each pane's `setTheme`). `tokens.json`'s `term-cursor` and `term-selection` are not used by the window and `TestTokensMatchJSON` skips them; `TestTerminalCursorIsTheTextColourAndSelectionTheAccents` checks the eight macOS accents and graphite in both themes.
- **Meaning colours do not follow the accent**: Read-only, Changes state, Destructive, Production, the pane warning, the live / connecting / dead dots, results, diffs (`TestMeaningColoursDoNotFollowTheAccent`).
- **Lines.** One divider colour for seams and control outlines, MyGo's `Border` (measured on the bars: light 1.28:1, dark 1.70:1; on the stage 1.37 and 1.89). A seam is not fainter than a field, and the light one is faint: MyGo's own light border is that quiet. `lineStrong` (Border toward Text by 35%) is for the unfocused ring and the few custom outlines. Hairlines are one DIP, one colour, never two touching (`TestSeamsAreOneLineOfOneColour`).
- **Window opacity.** A control over the ground covers 0.8 of the backdrop at opacity 0.7 (`controlShare` 2.2, `controlFloor` 0.2); the contrast floor of `minControlAlpha` holds. At opacity 1 nothing changes; dialogs, menus, toasts and the palette stay opaque (the theme is set again, opaque, before they are built). **The window has no shadow, at any opacity.** The window server cuts a Transparent window's shadow from its content's alpha and shows it through the translucent grounds, and MyGo asks for it to be cut again (`invalidateShadow`) only when it makes the window, so the first page's shadow stayed under every later page, worst at opacity 30 and in the dark theme. `setWindowHasShadow(win, false)` (`setHasShadow:NO`, `blur_darwin.go`; a no-op off macOS) runs when the window shows; an older `keel-native.json` that has `windowShadow` still loads, the key is ignored and the next save drops it. **The window border** (`windowborder.go`): without a shadow the edge is lost against the desktop, so a 1 pt line in the strong line token (`lineStrong`, full alpha, not translucent with the grounds) is drawn round the window in the root view, above the grounds and under the toasts and dialogs, as an Absolute box with no pointer event and no focus, so nothing in the layout moves. MyGo and AppKit have no border for a titled, hidden-title-bar window, hence drawn; its corners use the system's radius for the window, 10 pt before macOS 26 and 16 pt from macOS 26 (`windowCornerRadius`; not read from AppKit, which has no call, and the 16 is not verified on macOS 26). None in full screen (`Context.TitleBar` is zero), none off macOS. Held by `windowborder_test.go` (four edges, the arc, both themes, opacity 100 and 30, none in full screen, layout unchanged) and `tests/native-automation/border_test.go` (the real window's own render). The socket's capture never shows the ghosting; `TestNoGhostUnderLowOpacity` photographs the screen over a solid window of its own (`tests/native-automation/backdrop.swift`, built with `swiftc`; the test skips without it) and checks that an empty part of the pane is one flat colour.
- **While the model works**: `loading.Blocks` (`workingBlocks`), labelled "Agent is working" (the in-pane suggestion: "Suggesting a command"), beside the unchanged text in the agent panel and the Agent page and in the suggestion card. It shows only while the ask or the suggestion is in flight and stops on an answer, an error, Stop and a timeout (`working_test.go`, `suggestpane_test.go`); under reduced motion the plugin stands still. Nothing else uses it: Propose again, drafting a runbook and saving a provider key do not reach the provider.

### Custom looks and pieces

- **Pane focus ring.** The focused tile has a 1.5 px `focus` border painted over its own edge (so the tile and the gap never move when focus moves), plus one soft glow (8 px blur, `focus` at 18% dark, 12% light). Every other split tile has a 1 px `line` border. A single pane or a zoomed one has neither; a window that is not the active one falls back to `line-strong` and no glow; nothing animates. Notebook tiles are the same. The unfocused pane's terminal text dims to 70% but its body keeps the stage.
- **One empty state** (`empty.go`). A page size (round tile, title, two lines, at most one primary and one quiet action, about 38% down the free height) and a side size (small icon, title, caption, optional text button), for nothing yet, no match for the filter (title names it, "Clear filter") and cannot load ("Try again"). The Recently deleted and History dialogs' empty lines, the notes list lines, the run page with no hosts open, and the runbook source menu's "No notebooks" line are still plain help text.
- **Flat key caps.** One face (`keyCapFace`) for the inline cap and the one shown while ⌘ is held: a 1 px border on all four sides, `radius-xs`, no shadow, no thicker bottom edge. Inline is `surface` with a `line` border; held is opaque `raised` with `line-strong`.
- **Dialogs and small controls.** Dialogs wear MyGo's Modal chrome (`modalChrome`, `controls.go`: the dimmed backdrop, the theme's panel, radius, border and shadow, on `ui.DialogBase` because `ui.Modal` cannot set the panel's width, label or keys), and every confirm opens with the keyboard on Cancel with the destructive action never the default (`TestEveryConfirmStartsOnCancelAndEnterDoesNotDestroy`), as the typing dialogs do. Check boxes (`ui.CheckboxState`, with the mixed dash), radio groups (`ui.RadioGroup`) and First run's choice cards (`ui.RadioBase`) are MyGo's. Neutral badges and counts are `ui.Badge` (`neutralBadge`); badges that mean something (Edited by agent, a failure, Already saved, Trusted) are the same pill in the meaning's colour. A wait that does not end at the model shows `ui.Spinner` (`waitHelp`, `busyMark`: loading lists and notes, Connecting, Test connection, saving, restoring, the group run's fill, Creating link). Icon-only controls, tab names, host and folder names carry a tooltip; truncated rows in Keychain, Snippets and Runbooks carry a tooltip with the full text.
- **Pieces with no MyGo counterpart**: the exact-bytes box, the risk and Production badges, the proposal and run cards, role chips and tags, the pane tile and its ring, the terminal, key caps, the palette, the host and recent cards, First run's setup progress row (MyGo's `Stepper` is arrows, not steps), the radio mark inside a choice card, the host picker (second-line descriptions).
- **Lists, sidebar and bars.** The Snippets and Runbooks page lists are `ui.List` (virtual rows, Up / Down / Home / End choose, the row's menu and switch stay). Custom because a MyGo component cannot carry what they do: the Keychain list (section headers between rows), Port forwarding, Logs, conversations and the group tables (cards, not uniform rows); the sidebar (`ui.Sidebar` has no drag onto folders, row menus, inline rename, ⌥↵ or ⌘-hold key caps). The sidebar is resizable from its right edge (`sash.go`, the agent panel's sash generalised; drag, ← → step by space-4 and ⇧ four times, Home and End, double click or Enter for the default; kept as `sidebarWidth`); sharing the sash with the agent panel means Enter resets the agent panel's width too, and End saves the clamped width. Its minimum width is the four labels' width (246 at the default UI size, a little under the default 252; wider off macOS), its other bounds up to twice the default, so above the default UI size the width is no longer a fixed px. The chosen row of the sidebar (the host or pane of the focused pane; `chosenRow`, `controls.go`) has `ui.Sidebar`'s source-list look: the accent with its text colour while the sidebar's list has the keyboard in an active window, the neutral grey otherwise and in an inactive window (`chosenrow_test.go`); on the fill the host's tile and the row's "…" icon take the on-accent text colour (`rowTile`, `iconMenuBtnIn`). The Settings section list is `ui.Sidebar` (two, so About Keel sits under a spacer and the arrow keys stop at the seam above it). The tab strip (`ui.Tabs` has no drag reorder, drop-a-pane-to-tab, close buttons, page glyphs or key caps) and the title bar (traffic-light inset, full screen; `ui.Toolbar` would add a tab stop and an overflow menu over the tabs) are custom; the agent panel's sash is custom (`ui.Split` keeps only 40 DIPs from each edge, with no clamp to half the window, no Home / End or ⇧ steps, and the saved width is the panel's); so is the find bar's frame (`ui.FindBar` has its own labels and count and counts matches the terminal does not expose; its step and close buttons are MyGo icon buttons); seams are `hairline`, the theme's quiet `line` (`ui.Divider` is the heavier control border). Share, Agent, Delete all, Stop runtime… and Delete identity are MyGo buttons.

### Only a person can check

- Real blur behind the translucent controls, and the pane ring in a real window when it loses and regains key status (the Tester's `SetWindowActive` stands in).
- The accent changing while the window runs (the frame follows `Preferences`; the Tester cannot change it), VoiceOver names (every icon button has a name and a tooltip).
- The chords of the menu bar (a menu key going to the menu and not the view), the menu bar item and its menu (status, Show/Hide, New Tab, Quick Connect…, the Claude Code switch, Quit Keel), that the Dock, the menu bar item or Finder brings a closed window back (`make native-automation` shows the window hidden and the app alive, and Quit through the menu), the stale-runtime toast against an older `keel serve`, `Keel.app` from the release on an Intel Mac (its universal libghostty-vt was never run on x86_64 here), the `.app` opened from Finder (ad-hoc signed, not notarized), Keychain mode (the harness runs `KEEL_KEYRING=off`), sharing across two machines and NAT, a public signal server and the browser join page against a native owner, one real provider question (every machine test runs `KEEL_AGENT_PROVIDER=fake`), ⇧+click and ⌘-click chords the Tester cannot send, the system clipboard, input methods, the macOS save dialog behind Download (the tests give the window their own), and the whole Linux desktop window.

## What the window does not do

- **Previous command / Next command** (the palette actions, shell integration marks). The terminal plugin keeps the marks (OSC 133) for itself and exposes no call for them, and has no public call to scroll to a row or by lines (`Terminal` has `Search`, `SearchNext`, `SearchPrevious`, `Snapshot`, `Text`, `Size`, `Resize`, `ClearScreen`; scrolling is behind the `ActionScroll*` key bindings only). Keel could note each `OSC 133;A` in the bytes it already hands to the terminal but could not scroll to it. Missing in `plugins/terminal.Terminal`: a `ScrollBy(rows int)` / `ScrollToRow(row int)`.
- **The terminal's right-click menu with Find, Split right, Split down and Close pane.** With Right-click set to Menu the plugin shows its own menu (Copy, Paste, Select all, Clear) and has no hook to add items; a menu of the window's own could not copy the selection or select all (the plugin returns neither), and a Keel-made Copy, Paste or Select all would be a new writer or a selection read the plugin does not offer, so the plugin's menu stays whole (Find and the splits are in the File and View menus and the palette). The setting applies to new panes only (the plugin takes it when a terminal is made). Missing: an `Options.ContextMenu func(*ui.Menu)` (extra items after the plugin's) or `Terminal.Copy()` / `Terminal.SelectAll()` / a view-owned paste call.
- **Find bar Match case.** The plugin's search ignores the case of ASCII letters and reports only the count and the selected match's place (`SearchStatus`), not the matched text, so the client cannot filter matches itself: `Search(text)` has no options, and Keel could search `Snapshot` text itself but cannot select a range or scroll to it. Missing: a `Terminal.SearchCase(bool)` (or `Search(text, SearchOptions{MatchCase})`).
- **Menu icons in the agent cards' right-click menus.** MyGo's menu icons are images made once with `mygo.NewMenuIconSVG`, which needs the window system; no menu in the window draws an icon.
- **Single instance** (MyGo has `RequestSingleInstanceLock`; the window does not take it).
- **A one-click read-only group step** (§6 rule 13): every group step goes through the dialog.
- **Markdown in the agent's answers**: the answer is shown as the characters the model wrote (no headings, lists, links, tables or images). ⇧↵ on a focused Type button is not offered, because MyGo gives a button pressed from the keyboard no modifier (a ⇧ proposal's button shows ⇧ and takes ⇧ held on a click, and ↵ is a plain Type, which is refused for it).
- **Streaming** of the agent's answer, and **Claude Code through `keel mcp`** from the window (the Settings switch is built; the window never calls its routes).

Different on purpose:

- The notebook is read rendered and edited as Markdown source; one over 64 KiB opens in Edit ("Notebooks").
- Right-click in the terminal, Copy on select and the other terminal settings are the plugin's: Copy on select and the text size apply at once, Right-click applies to new panes; the plugin's menu is fixed.
- Window opacity and blur have no counterpart elsewhere; Font smoothing has no meaning for MyGo's own text.
- A joined tab takes no snippet and no Approve before type (a joined pane has no runtime id), so "Open a session first" is the answer there.
- A session killed from another window shows "Session ended" with Close in this window; the host rows' session counts follow the panes of this window. The window reads `GET /api/sessions` when it opens, and each pane's own connection reports its state, presence and end.
- The host key dialog also shows the key type ("ssh-ed25519") on its own line; Unlock's "Try the keychain again next time" is a checked, disabled box with no effect; the Keychain page shows no fingerprint, comment, public key or algorithm badge (the server redacts them).
