# keel-native

`keel-native` is a second Keel client: a native window drawn with [MyGo](https://github.com/egoist/mygo) and libghostty terminals, not a webview. It is the first step of leaving the webview. The goal is the same features and the same look as the app; the webview app (`keel app`) keeps shipping unchanged until the last phase.

It is a client only. It needs a running `keel serve`, which still owns SSH and the PTYs, and it never reads the keychain or the vault: it sees what `keel serve` returns on loopback, with the token from the data directory.

## Run it

```sh
keel serve &            # or let Keel.app start it
make native             # builds bin/keel-native (pure Go, no cgo)
./bin/keel-native
```

`make native-app` builds `bin/Keel Native.app`: `keel-native` with libghostty-vt beside it in `Contents/MacOS`, so the app never downloads the library. The library comes from MyGo's loader (SHA-256 checked); the bundle is ad-hoc signed, not notarized, and is a developer bundle until the cutover (N9).

`KEEL_DATA` and `KEEL_ADDR` select the data directory and address, as for `keel serve`. From a checkout, run it in the repository root so it finds the JetBrains Mono fonts in `cmd/keel/web/fonts`; elsewhere it falls back to the system monospace. The first run downloads libghostty-vt into the user cache (SHA-256 checked by MyGo).

## Verifying

`make native-e2e` builds `bin/keel` and `bin/keel-sshtest` and drives the real window under MyGo's `ui.Tester` against a scratch `keel serve` it starts per test (scratch data in `.scratch-native/e2e/`, one PNG per scenario). It needs macOS and does not touch your Keel.

## What works

- Host tree grouped by group, with a filter on name, address and username. Click a host to open it in a new tab (or in the New tab that is showing).
- Tabs with a state dot and a pane count badge; `+` and ⌘T open a New tab (below).
- Split → and Split ↓ (another PTY to the same host), drag the gap to resize, close a pane (kills its PTY; the last pane closes the tab).
- Live terminals; the focused tile gets the soft ring and the others dim in a split tab.
- The workspace comes back. The tabs, how each is split (direction and ratio), custom tab titles, the focused and zoomed pane of each tab and the active tab are saved in `keel-native-workspace.json` in the data directory (session ids, titles and layout only: no host, user, address or secret; mode 0600, written atomically, debounced and on window close). A window reopens with the same tabs and splits. Sessions that are gone drop out of their tab and the tree closes up; running sessions that were in no saved tab become tabs after the saved ones; a missing, unreadable or other-version file gives one tab per session. A restarted `keel serve` gives new session ids, so nothing restores after a daemon restart. Closing the window detaches; sessions keep running.
- Status bar: session count, focused pane size, encoding.
- Focus view: ⌘⇧↵ or the pane bar's Focus view tool shows the focused pane alone and keeps the others' sessions; splitting or closing the zoomed pane leaves it.
- The pane menu, from the pane bar's **More pane actions** tool or a right-click on the pane bar: Split right, Split down, Focus view (with another pane beside it, or while zoomed), Reconnect (for a failed session), Close pane. (Share and the menu on ⇧F10 come later.)
- The tab menu, from a right-click on a tab: Rename tab, Close, Close others, Close to the right, Close all (disabled as in the webview). Rename edits in place: Enter or a click elsewhere keeps the name, Escape cancels, an empty name clears the custom title. Closing a tab kills its panes' sessions.
- Drag a tab onto another to reorder (it lands before or after it by which half the pointer is over); ⌘1…⌘9 follow the order. ⌘⇧[ and ⌘⇧] (also ⌘< and ⌘>) select the previous and next tab and wrap.
- ⌘⇧T reopens the last closed tab or pane as a new session on the same host, in a new tab or in the New tab that is showing (up to 10 are remembered for this window; none across a window close).
- The command palette, ⌘K or ⌘⇧P, a modal styled as the webview's (`k-palette`): the input, then **Open now** (every tab, and each pane of a split tab, with its state dot; choosing one focuses it and never starts a session), **Hosts** (↵ a new session in a new tab, ⌥↵ in a split right of the focused pane) and **Actions**, with the webview's titles, section hints and key caps. Every word of the query must appear in a row's title, hint, group or keys; the matched text is highlighted. ↑ ↓ wrap and keep the row in view, ↵ runs, esc (or ⌘K again) closes and returns the keyboard to the pane. While it is open no key reaches a terminal and no window shortcut acts. Actions it has: New tab, New Local Shell, Close pane or tab, Reopen last tab, Previous tab, Next tab, First tab, Last tab, Toggle vault sidebar, Quick connect, Split right, Split down, Focus view (zoom pane), Find in terminal, Larger text, Smaller text, Reset text size.
- The New tab page (⌘T, `+`, and what an empty window shows; closing the last tab leaves one, and ⌘W on the lone New tab does nothing). "Where to?", one input (a saved host, `user@host:port`, or a pasted `ssh …` command), the recent host cards (up to 6, `⌥1`-`⌥6` open them; the local shell is always first; a query filters every host by name, group, address and user, recent ones first), the **Start** action Quick connect (⌘⇧O), and **Recently closed** (up to 3, with their age; a row, or ⌘⇧T for the newest, starts a new session on that host). ↵ opens the highlighted card (↑ ↓ move it). Opening a host fills the New tab that is showing. A New tab is not written to the saved workspace. Recent hosts are kept as host ids only, newest first, up to 12, as `recentHosts` in `keel-native.json`.
- A pasted command is parsed, never run (`internal/native/sshparse`, a port of `lib/sshparse.js` with the same cases as its test): no shell, no `ssh` binary, no key file read, no lookup. The page shows "Read as `user@host:port`. Nothing has run.", what was **left out** and why (a command that runs something, host-key trust changes, forwards, a jump host, config files, a remote command) and a key-file note. **Connect once** (needs a user) opens the Quick connect dialog, as in the webview: the target is prefilled, the user types the password (never taken from the pasted text), and **Connect** saves a password host named `user@host` in the group "Quick connect" with `POST /api/hosts` and opens it; the host key dialog follows. Quick connect (⌘⇧O, the Start action, or the palette) is the same dialog with an empty target; its target is read with the same parser, which takes `user@host`, `user@host:port`, `ssh://…` and a pasted command.
- ⌘F finds in the focused terminal with the terminal's own search: a find bar above it with the match count, previous and next, and close. Enter and ⌘G go to the next match, ⇧Enter and ⌘⇧G to the previous, Escape closes. Nothing is sent to the session.
- ⌘+ (⌘=), ⌘- and ⌘0 set the terminal text size of every pane, 10 to 22, default 12, kept as `termSize` in `keel-native.json` (the other fields of that file stay as they are).
- Keys: ⌘1…⌘8, ⌘9, ⌘W, ⌘T, ⌘N, ⌘K, ⌘⇧P, ⌘⇧O, ⌘⇧D, ⌘⇧E, ⌘⇧↵, ⌘⇧T, ⌘⇧[ ⌘⇧], ⌘F, ⌘G, ⌘⇧G, ⌘+ ⌘- ⌘0, ⌘B, and ⌥1…⌥6 on the New tab page (Ctrl off macOS).
- Window translucency: the window is see-through at the saved opacity (default 66, range 30-100) with a macOS background blur (default 20, range 0-64; a private window-server call that falls back to no blur and logs once to stderr). All three are read from `keel-native.json` in the data directory, `{"opacity": 66, "blur": 20, "termSize": 12}` (the file also holds `recentHosts`, a list of host ids); the N5 Settings page will write opacity and blur (the text size keys already write `termSize`); `KEEL_NATIVE_OPACITY` and `KEEL_NATIVE_BLUR` override them for development, and an out-of-range value is an error.
- JetBrains Mono is embedded, so the bundle needs no font files beside it.
- Unlock (§5.14). A vault that exists and is locked (the keychain did not answer, or it uses a passphrase) shows the Unlock screen in place of the window, laid out and worded as the webview's: the mark, "Unlock your vault", the lead with the number of sessions waiting in keel serve, the banner for the vault's mode (keychain vault, `KEEL_KEYRING=off`, or a keychain that does not hold the key), the masked "Vault passphrase" field with a show/hide control, **Unlock** (↵), and the two statements (a lost passphrase cannot be recovered; running sessions keep working). A wrong passphrase shows "That passphrase doesn't open the vault." and keeps the keyboard in the field. The passphrase is sent in the one `POST /api/vault/unlock` and cleared from the field when it is sent; it is in no log, file or error. A locked vault shows Unlock whatever its first-run flag says (as the webview's gate does). A vault that still needs setup, and an unlocked vault whose first run is open, show First run (next).
- First run (§5.15). A vault that needs setup, or whose first run is open, shows the three steps in place of the window (`gate.templ` firstRunScreen and agentStep, with the flow of `gate.js`), under a progress row Vault · Hosts · Agent. **Step 1** is "Welcome to Keel": the keychain card and the passphrase card, the Passphrase and Repeat passphrase fields (with "Choose a passphrase." and "The passphrases don't match." before any request, and the server's own words after one), "Keel can't recover the vault if you lose the passphrase.", the vault file, its encryption and what it holds, **I already have a keel.vault…** (the webview's instruction text only: it quits, puts the file in the data folder and opens Keel; no file picker), and **Create vault** (`POST /api/vault/setup` with the passphrase, once). The keychain card is the webview's: it is the choice already made. With `KEEL_KEYRING=off`, or when the keychain did not answer, it is disabled with the webview's reason; on a vault the keychain made, it is the checked card and the button says **Continue**. keel serve makes a keychain vault itself, so there is no request for that choice (and a machine test cannot make one: the harness runs with `KEEL_KEYRING=off`; a person checks the keychain path once). **Step 2** is "Bring your hosts": the table of `GET /api/ssh-config/preview` with a checkbox per host (the rules of `lib/onboard.js`, with the cases of its test in `onboard_test.go`: new direct hosts start ticked, saved hosts and ProxyCommand/ProxyJump hosts start off, "Already saved", the Via flag and **Without the jump**, wildcard patterns listed apart, the notes, select all), then **Copy private keys into the vault** (one switch per key, off by default, a masked passphrase field for an encrypted key, "Enter the passphrase for <key>, or turn this key off.", "That passphrase doesn't open <key>."). **Add hosts** sends exactly the ticks and the keys turned on (`POST /api/ssh-config/import`); the result ("Added 2 hosts and 1 key. Not added: …") shows under the next step. **Back**, and **Skip, add hosts later**. The server reads the ssh config (`KEEL_SSH_DIR` in keel serve); the client never opens `~/.ssh`. Key passphrases and the vault passphrase are sent once and cleared when sent. **Step 3** is "An agent that suggests, never types": the three promises, **Back**, **Set up later** and **Open Keel** (both `POST /api/first-run/done`, then the workspace). A second window on the same daemon opens straight to the workspace. The command palette's **Import hosts from ~/.ssh/config** opens step 2 on its own (title "Import hosts", **Cancel** and Esc instead of Skip, no progress row or Back), and its result shows in the status bar.
- Tab pages. Keychain, Snippets and Logs open as their own tab (one each: opening it again selects it; the tab has the page's name and glyph, cannot be renamed, closes with ⌘W or the tab menu and is reordered with the others). They are saved in `keel-native-workspace.json` as `pages` (names only, no content) with `activePage`, and come back after the session tabs, in order. The sidebar footer has **Keychain** and **Logs**; the palette has them, and Snippets, as actions and lists an open page under Open now. ⌘N on Keychain is New identity, elsewhere New host. The mechanism (`pages.go`: a `pageDefs` entry, a state type and a view) is what Forwards, Notebooks and Settings plug into.
- How Keel types for you. Keystrokes from the terminal view are the only thing that reaches a session unasked. Everything else Keel types goes through **Approve before type** and one function: `(*keelclient.Conn).ApprovedInject` in `keelclient/inject.go` is the only code that sends an inject frame (a text frame the server answers with a one-time nonce, then the same bytes with that nonce, as `cmd/keel/web/js/pty.js` does), and its only caller is the dialog's Type action (`approve.go`); `guard_test.go` fails if another file sends the frame, calls it, names the Type action, or calls `Write` on a connection. keel serve writes exactly the bytes it is given for a nonce it issued for those bytes to the driver (`internal/runtime/runtime.go` InjectTicket) and adds nothing, so the client builds them as the webview does (`term.js` paletteRunSnippet): the command gets a trailing newline if it has none, the dialog shows that text, and what is sent is Ctrl-U (it clears the line first, as the dialog says) followed by exactly that text. The dialog is the webview's (title "Type into the terminal?", its sentence, "Session:", the text in the mono font as it is, Cancel and Type; the keyboard starts on Cancel). Opening it, Escape, Cancel and a click outside send nothing; no nonce is requested before Type; the preview is asked for again every frame and when Type is pressed. Type is off, with the webview's words, when this client is following ("You are following — take or request control to type") or the session is not ready ("Session is not connected"); a missing nonce (keel serve says nothing to a bad request) ends after 2.5 s with "Session is not connected" and nothing is typed, and Keel never retries. There is no production or ⇧ rule for snippets: the webview has none (it lives in agent proposals).
- Snippets (§5.12, as the app has them). The Snippets page: a list (name and first line) with a filter and **New snippet**, and the selected snippet's editor: its name, **Type into pane…**, **Save** (⌘S), the Commands text area ("One command per line. Each line ends with Enter when typed."), **Delete snippet** (asks: "Delete snippet “<name>”?"). The row menu is Type into pane…, Copy, Edit, Delete; New and Edit open the webview's snippet dialog (Name, Command, **Save snippet**). A save trims the name and ends the command with a newline, as `/ui/forms/snippet` does, and never sends the agent flag, so keel serve keeps it. The sidebar has the segmented control **Hosts · Snippets** (each with its own filter); the Snippets section lists every snippet and **Manage snippets**; a click, like the palette's **Type snippet: <name>** (group Snippets, after Actions) and **Type into pane…**, opens Approve before type for the focused pane (from a page, the session tab shown last). It uses the saved snippet, not unsaved editor text. ⌘N on the page is New snippet. The page is saved with the other tab pages.
- The Keychain page (§5.11). A list (SSH keys, then Passwords, each row with its kind, user and "N hosts", and a "passphrase" badge) with a filter and **New identity**, and the selected identity beside it: kind and date added, Username, what is stored ("Encrypted in the vault", "Stored in the vault", "Not stored", "None"), the hosts that use it, **Edit** and **Delete identity**. The identity dialog is the webview's (Name, Username, Kind, then a Password, or a Private key and a Key passphrase; blank secrets are left out so the server keeps the saved ones; the secrets are cleared when it closes or the request is sent). The page never holds, shows or copies a private key, a passphrase or a password: `keelclient.Identity` has no field for one. An identity a host still uses cannot be deleted: its Delete is off, with "Remove it from N hosts before you can delete it." (keel serve itself would clear it from those hosts, so the rule is the page's, as in the webview). Delete asks first.
- The Logs page (§5.13). "What Keel did on this machine, newest first. Secrets are never written here.", a search box (kind and message), the chips All, Sessions, Forwards, Vault and Agent (the webview's chips; it has no Sharing chip), **Refresh**, and the rows: time, kind, target (the host), event, with the counts of an agent entry. It reads again when it opens or is selected, on Refresh, and when the vault's `rev` changes. keel serve logs a host's creation and a trusted key, but not a host's deletion.
- New host and Edit host: one dialog (760 px, two columns) as the webview's: General (Label, Folder, Color, Tags), Connection (Hostname / IP, Port, Username, Jump host), Authentication (Password, Private key, Identity, Local shell; the host key line with **Forget host key**, which asks first), Session (Startup command, Keepalive and its interval, Auto reconnect) and Agent (Agent can read this host's panes, Treat as production, Let the agent propose notes). Footer: **Delete host** (Edit only, asks first: "Remove <name>?"), **Test connection** with its inline result, Cancel, **Save host** (⌘↵). Escape or Cancel closes without a request and clears the secrets. Typed secrets (password, private key, key passphrase) go only in the Save or Test request; a blank secret on an update is left out of the body, which the server reads as "keep the saved one" (`internal/store/store.go` putSecretLocked); the dialog never shows a saved secret. Server refusals ("name is required", the jump host rules) show under the fields. Entry points: the sidebar `+`, ⌘N, the palette's New host, the New tab page's Start action New host, **Save as host** on a pasted command (↵ in the page's input too; the dialog is prefilled with its target and notes, nothing is saved until Save), the failure banner's **Edit host**, and the host menu.
- Test connection connects and authenticates with the dialog's unsaved values, then closes (no PTY, no command; 10 s, cancellable with **Cancel test**). The result uses the webview's texts for every outcome (Connected in N ms, Authentication failed, Host key unknown, Host key changed, Timed out, Host not found, Connection refused, Test cancelled, Could not connect, and the jump-host prefixes). An unknown or changed key shows its fingerprint and a separate **Trust and save** (**Replace saved key**, which asks first) button: only that click sends the server's own offer to `POST /api/known-hosts`, and it then tests again. The test never trusts on its own, and editing a field the test used drops the result.
- The host menu, from a right-click on a host row or its "…" control: Connect, Open in split (⌥↵, also on a focused row), Edit, Duplicate, Agent can read, Delete (asks first). The local shell has no Duplicate or Delete. Deleting a host leaves its open sessions running, as in the webview: the pane keeps its last known host, and its Edit host says "Host not found".
- The host list stays current. The hosts are read again after every write the window makes, and a poll of `GET /api/vault` every 3 s while the window is open (none after it closes) reads them again when its `rev` changes; the filter, the collapsed groups and the open tabs stay. If the poll finds the vault locked again, the Unlock screen covers the window and sessions and tabs stay as they were; if another window unlocked it, the screen goes away.
- Pane states, with the webview's words. A session that is down (exited, or failed) shows a flare banner, "Session ended", "Connection lost" or "Connection failed", with its endpoint and the server's last message, and **Close** and **Reconnect**. Sessions that were already down when the window opened come back as tabs with that banner. A non-local session that is connecting shows a signal "Connecting…" banner.
- A first connection to an unknown host key, or a changed key, opens a dialog for the focused pane: host, key type, fingerprint (and the saved one for a changed key). **Trust and connect** sends the server's own offer back and reconnects; **Abort** or Escape leaves the pane with its banner. Nothing else trusts a key.
- A session another window also attached shows a role chip (Driving, Owner, Following) in the pane bar. Anyone who is not driving sees a haze banner ("Following · <name> is driving · read-only", or "Nobody is driving") with **Take control** for the session's owner and **Ask for control** for everyone else; keel serve drops a follower's keystrokes. Passing control (Grant) has no UI yet: it is part of the share phase.
- The area outside a tile's rounded corners is chrome under window translucency, once.
