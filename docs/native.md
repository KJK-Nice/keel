# keel-native

`keel-native` is a second Keel client: a native window drawn with [MyGo](https://github.com/egoist/mygo) and libghostty terminals, not a webview. Since cutover stage 1 it is the window `keel app` opens, in the same process as `keel` (`internal/app/run_native.go` calls `native.RunWith`; MyGo is purego, so it links into the cgo binary without trouble). The previous window, the Wails webview, is still built and opens with `keel app --webview` (or `KEEL_UI=webview`; `KEEL_UI=native` is the default and any other value is an error). Stage 2 removes the webview, Wails, templ, Tailwind, `cmd/keel/web` and the web e2e tests.

It is a client only. `keel serve` still owns SSH and the PTYs, and the window never reads the keychain or the vault: it sees what `keel serve` returns on loopback, with the token from the data directory (`X-Keel-Token`, never a cookie or an `Origin`).

## Run it

```sh
make build              # bin/keel and bin/Keel.app (libghostty-vt beside the binary)
./bin/keel app          # or just ./bin/keel, or open bin/Keel.app; make app from a checkout
./bin/keel app --webview   # the previous window; make app WEBVIEW=1
```

`keel app` does what the webview did before its window, in the same order: it makes the data directory (0700), loads or creates the token, starts `keel serve` if it is not running (`EnsureServe`) and checks that it answers to that token (`VerifyServe`). It then opens the window on that address and data directory (`KEEL_ADDR`, `KEEL_DATA`, from `internal/paths`). It does not re-exec into `~/Library/Caches/keel/Keel.app` (`desktop.EnsureMacApp`): that exists because WKWebView needs a signed bundle with JIT entitlements, and the native window needs none. A bare `./bin/keel` therefore has no bundle icon or name in the Dock and menu bar; `bin/Keel.app` has. `--name` sets the share name for the run (it sets `KEEL_NAME`, which the window already reads for Settings · Sharing and for its sessions).

If the `keel serve` that answers is from another build than the app, the window shows a toast with the app's words ("The Keel runtime that's running is from a different build than this app…") and a **Stop runtime** button that asks first. The build id is `internal/buildid.Of`: the VCS revision plus a hash of the embedded web assets. `keel serve` and `keel app` are the same binary, so both compute it the same way; after the web assets are gone the hash part is the constant "noweb" and the revision still tells builds apart, so the check does not depend on them. The webview's banner stays until a user dismisses it; the toast lasts the usual five seconds.

`bin/Keel.app` is the bundle id `app.keel.desktop` it has always had. Changing it would orphan the Keychain items and user defaults that are tied to that id; the native Info.plist has the same keys, so there was nothing to merge. `make native-app` stays: it builds the attach-only `bin/Keel Native.app` (`app.keel.native`) from `cmd/keel-native`, which keeps working on its own (it needs a running `keel serve`, and `KEEL_DATA`/`KEEL_ADDR` select it).

### The app shell

The Wails shell, and what the native window has of it (`internal/native/shell.go`; the menu items run the window's own actions and add no writer):

| Wails shell behaviour | Native |
|---|---|
| App menu (About, Hide, Quit ⌘Q), Window menu | built (MyGo `RoleAppMenu`, `RoleWindowMenu`) |
| File menu: New Tab ⌘T, Close Tab ⌘W, Reopen Tab ⌘⇧T, New Host ⌘N, Quick Connect ⌘⇧O, Join Session ⌘J, Split Right ⌘⇧D, Split Down ⌘⇧E, Split Notebook, Close Window ⌘⇧W, Stop Keel runtime | built; Find Host (no chord, a page-JS action) is the sidebar filter and the palette instead |
| View menu: Find in Terminal ⌘F, Toggle Vault Sidebar ⌘B, Toggle Agent Panel ⌘I (Ctrl+⇧I off macOS), Focus View ⌘⇧↵, Zoom In ⌘= / Zoom Out ⌘- / Actual Size ⌘0 | built; the chords were already the window's own (`shortcuts`), and a chord that is a menu item's goes to the menu, which runs the same function |
| Edit menu | not built on purpose: its ⌘C/⌘V roles would take the keys from the terminal's own copy and paste |
| Menu bar item (tray) with serve status, Show/Hide, New Tab, Quick Connect…, Allow Claude Code, Quit Keel | built (macOS only, as before; MyGo `NewTray`, the same template icon) |
| Keep in menu bar: closing the window hides it and the Dock icon, the menu bar item or opening Keel again brings it back, Quit quits | built (macOS only; `Window.OnClose` + `App.Dock.Hide/Show` + `App.OnActivate`) |
| Window size and position remembered | the webview never did (`desktop.Run` drops its profile argument); MyGo can (`WindowOptions.StateKey`, `App.SetWindowStateStore`), not built |
| Single instance | the webview never had one; MyGo has `RequestSingleInstanceLock`, not built |
| Appearance follows the OS and the theme choice | already built (`mygo.Theme.SetSource`) |
| Full screen, traffic lights, translucent window and blur | already built |
| Close the window to detach; sessions stay in `keel serve` | already built (`closeWindow` detaches) |

Nothing in the shell is missing an API in MyGo v0.8.3. None of it can be reached by the headless tester: the menu bar, tray, Dock and close behaviour are on the person-only list below. The tests cover the tables (`shell_test.go`): labels, chords per OS, and that each action does what its chord does.

`KEEL_DATA` and `KEEL_ADDR` select the data directory and address, as for `keel serve`. The fonts (JetBrains Mono, IBM Plex Mono) are embedded (`internal/native/fonts`). A binary that has no libghostty-vt beside it (a bare `./bin/keel`, `go run`) downloads it into the user cache on first run (SHA-256 checked by MyGo); `bin/Keel.app` and the release archives carry it, so they never download.

## Verifying

`make native-e2e` builds `bin/keel`, `bin/keel-sshtest` and `bin/keel-signal` and drives the real window under MyGo's `ui.Tester` against a scratch `keel serve` it starts per test (scratch data in `.scratch-native/e2e/`, one PNG per scenario). It needs macOS and does not touch your Keel.

## What works

- Host tree grouped by group, with a filter on name, address and username. Click a host to open it in a new tab (or in the New tab that is showing).
- Tabs with a state dot, a pane count badge and a close button (16 px, shown while the pointer is over the tab; with ⌘ held the W cap stands in for its glyph on the selected tab); `+` and ⌘T open a New tab (below).
- Split → and Split ↓ (another PTY to the same host), drag the gap to resize, close a pane (kills its PTY; the last pane closes the tab). Drag a pane bar onto another pane of its tab: an edge moves it beside that pane, the centre swaps the two, the region it would take is drawn while the pointer is over (`panedrag.go`, `layout.Beside` and `Swap`, from `lib/workspace.js` movePane). A tab dropped on the empty strip after the last tab goes last. A pane dragged by its bar and let go on the strip (a tab, or the empty strip) becomes a tab of its own there (`extractPane`; a tab of one pane has nothing to leave), and a tab dropped on a pane of another tab docks all its panes beside that pane (`dockTab`, `layout.Dock`; the centre docks to the right; the region is drawn as for a pane), with Sync input on if either tab had it. No session is opened or closed by either (`panedock_test.go`). Joined tabs, the New tab page and page tabs take no part; notebook tiles are neither dragged nor dropped on.
- **Sync input** (plan 026): the pane bar's sync tool (pressed, "Sync input" / "Stop syncing input"; every terminal pane of a syncing tab shows it pressed, the only look the app gives sync: `.is-sync` has no rule of its own in `keel.css`), the status bar's "Sync on" / "Sync off" (not in a joined tab), and the palette's "Toggle sync input" (offered only in a session tab with a terminal; the app has no shortcut for it). While a tab has it on, the user's own keys and paste in one terminal go to every other terminal pane of that tab that this client drives and that is ready, as well as to the pane typed into. The flag is saved with the tab (`sync` in `keel-native-workspace.json`, as `savedworkspace.js` has it). How it is built, and why it is not an injection: "How Keel types for you" (the fifth writer).
- Live terminals; the focused tile gets the soft ring and the others dim in a split tab.
- The workspace comes back. The tabs, how each is split (direction and ratio), custom tab titles, the focused and zoomed pane of each tab and the active tab are saved in `keel-native-workspace.json` in the data directory (session ids, titles and layout only: no host, user, address or secret; mode 0600, written atomically, debounced and on window close). A window reopens with the same tabs and splits. Sessions that are gone drop out of their tab and the tree closes up; running sessions that were in no saved tab become tabs after the saved ones; a missing, unreadable or other-version file gives one tab per session. A restarted `keel serve` gives new session ids, so nothing restores after a daemon restart. Closing the window detaches; sessions keep running.
- Title bar, right: the line the app calls `#bar-status`: "<pane line> · driving" (or "· following") for a session, "New tab" or "Connecting…" on the New tab page, "No session", nothing on a page. Status bar: session count, the running forwards (`N forwards`, hidden with none), focused pane size, encoding.
- Focus view: ⌘⇧↵ or the pane bar's Focus view tool shows the focused pane alone and keeps the others' sessions; splitting or closing the zoomed pane leaves it.
- The pane menu, from the pane bar's **More pane actions** tool or a right-click on the pane bar: Split right, Split down, Focus view (with another pane beside it, or while zoomed), Share (for a live local session), Reconnect (for a failed session), Close pane. ⇧F10 and the Menu key open it from a focused control of the bar (MyGo's popover menus take them); in the terminal ⇧F10 stays the program's, as in the app.
- The tab menu, from a right-click on a tab: Rename tab, Close, Close others, Close to the right, Close all (disabled as in the webview). Rename edits in place: Enter or a click elsewhere keeps the name, Escape cancels, an empty name clears the custom title. Closing a tab kills its panes' sessions.
- Drag a tab onto another to reorder (it lands before or after it by which half the pointer is over); ⌘1…⌘9 follow the order. ⌘⇧[ and ⌘⇧] (also ⌘< and ⌘>) select the previous and next tab and wrap.
- ⌘⇧T reopens the last closed tab or pane as a new session on the same host, in a new tab or in the New tab that is showing (up to 10 are remembered for this window; none across a window close).
- The command palette, ⌘K or ⌘⇧P, a modal styled as the webview's (`k-palette`): the input, then **Open now** (every tab, and each pane of a split tab, with its state dot; choosing one focuses it and never starts a session), **Hosts** (↵ a new session in a new tab, ⌥↵ in a split right of the focused pane) and **Actions**, with the webview's titles, section hints and key caps. Every word of the query must appear in a row's title, hint, group or keys; the matched text is highlighted. ↑ ↓ wrap and keep the row in view, ↵ runs, esc (or ⌘K again) closes and returns the keyboard to the pane. While it is open no key reaches a terminal and no window shortcut acts. Actions it has: New tab, New Local Shell, Close pane or tab, Reopen last tab, Previous tab, Next tab, First tab, Last tab, Toggle vault sidebar, Search hosts (the sidebar shows Hosts and its filter has the keyboard), Quick connect, Split right, Split down, Focus view (zoom pane), Find in terminal, Larger text, Smaller text, Reset text size, and the pages, Join, Share, Import and Stop runtime named below. The last row, **Ask the agent** (⌘↵, Ctrl+↵ off macOS; the footer's "ask agent" cap), is there whatever the query matches, with no group heading: it opens the agent panel with the query in the composer and **sends nothing** (term.js `askAgentFromPalette`; the panel has no key yet, it shows its Connect card). One difference on purpose: with nothing matched the list still says "No matching commands" above that row (the app's list holds only the row).
- The New tab page (⌘T, `+`, and what an empty window shows; closing the last tab leaves one, and ⌘W on the lone New tab does nothing). "Where to?", one input (a saved host, `user@host:port`, or a pasted `ssh …` command), the recent host cards (up to 6, `⌥1`-`⌥6` open them; the local shell is always first; a query filters every host by name, group, the names of the folders above it, address, user and tags, recent ones first: `term.js` hostMatches over `lib/groups.js` hostSearchHay; the palette's host rows match their title and `user@address` only, as the app's do), the **Start** action Quick connect (⌘⇧O), and **Recently closed** (up to 3, with their age; a row, or ⌘⇧T for the newest, starts a new session on that host). ↵ opens the highlighted card (↑ ↓ move it). Opening a host fills the New tab that is showing. A New tab is not written to the saved workspace. Recent hosts are kept as host ids only, newest first, up to 12, as `recentHosts` in `keel-native.json`. Recently closed is kept across closing the window as `closedTabs` there (a host id, the title cut at 120 characters, "tab" or "pane" and a time; read as `lib/newtab.js` normalizeClosed reads it; the app keeps it in localStorage).
- A pasted command is parsed, never run (`internal/native/sshparse`, a port of `lib/sshparse.js` with the same cases as its test): no shell, no `ssh` binary, no key file read, no lookup. The page shows "Read as `user@host:port`. Nothing has run.", what was **left out** and why (a command that runs something, host-key trust changes, forwards, a jump host, config files, a remote command) and a key-file note. **Connect once** (needs a user) opens the Quick connect dialog, as in the webview: the target is prefilled, the user types the password (never taken from the pasted text), and **Connect** saves a password host named `user@host` in the group "Quick connect" with `POST /api/hosts` and opens it; the host key dialog follows. Quick connect (⌘⇧O, the Start action, or the palette) is the same dialog with an empty target; its target is read with the same parser, which takes `user@host`, `user@host:port`, `ssh://…` and a pasted command.
- ⌘F finds in the focused terminal with the terminal's own search: a find bar above it with the match count, previous and next, and close. Enter and ⌘G go to the next match, ⇧Enter and ⌘⇧G to the previous, Escape closes. Nothing is sent to the session.
- ⌘+ (⌘=), ⌘- and ⌘0 set the terminal text size of every pane, 10 to 22, default 12, kept as `termSize` in `keel-native.json` (the other fields of that file stay as they are).
- Keys: ⌘1…⌘8, ⌘9, ⌘W, ⌘T, ⌘N, ⌘K, ⌘⇧P, ⌘⇧O, ⌘⇧D, ⌘⇧E, ⌘⇧↵, ⌘⇧T, ⌘⇧[ ⌘⇧], ⌘F, ⌘G, ⌘⇧G, ⌘+ ⌘- ⌘0, ⌘B, ⌘I (the agent panel; Ctrl+⇧I off macOS), and ⌥1…⌥6 on the New tab page (Ctrl off macOS).
- Find: ⌘F's find bar has no Match case (see "What is missing").
- Window translucency: the window is see-through at the saved opacity (default 66, range 30-100) with a macOS background blur (default 20, range 0-64; a private window-server call that falls back to no blur and logs once to stderr). All three are read from `keel-native.json` in the data directory, `{"opacity": 66, "blur": 20, "termSize": 12}` (the file also holds `recentHosts`, a list of host ids); Settings · Appearance writes opacity, blur, `theme` and `uiSize` (the text size keys write `termSize`, Settings · Terminal `termFont`, Settings · Terminal `copyOnSelect` and `rightClick`, Settings · Sharing `name`; every other field stays as it is); the blur is set when the window shows and again when Settings changes it; `KEEL_NATIVE_OPACITY` and `KEEL_NATIVE_BLUR` override them for development, and an out-of-range value is an error.
- JetBrains Mono and IBM Plex Mono are embedded (copies of `cmd/keel/web/fonts`, with their OFL files; a test keeps them equal), so the bundle needs no font files beside it.
- Splits fit the window. Any split tree tiles the stage: every tile lies inside it, siblings are 6 px apart and each split's two sides share its width (or height) in its ratio, at any window size; a window too small for the tiles makes them narrower and clips their pane bars, as the webview's `computeRects` does, and nothing runs off the edge. (Each split divides the room it has by its own ratio, so four panes in a row are 1/2, 1/4, 1/8, 1/8 of the width until you drag a gap, as in the webview.) The cause of the earlier overflow was that the boxes holding the tiles had no zero minimum size, so a tile's pane bar held its natural width.
- Appearance · Theme: System (the default; it follows the OS appearance and changes with it), Light or Dark, kept as `theme` in `keel-native.json`. `tokens.go` holds both colour sets (`TestTokensMatchJSON` checks them against `docs/design/tokens.json`) and `useTheme` sets the colour variables at the start of each frame, so a view never names a theme. Everything follows: grounds, text, lines, MyGo's stock widgets, every open terminal's colours (`Terminal.SetTheme`), dialogs, toasts, the palette, the pages, Unlock and First run, the translucent grounds (the light terminal body keeps 30% of the see-through, `vibrancy-term-share`), and on macOS the window's own appearance (`mygo.Theme.SetSource`, as `internal/desktop/appearance.go` does for the webview, so the backdrop follows the choice). Where the window cannot take the theme (not macOS), a theme that differs from the OS's keeps the window opaque, and Settings says so as the app does; on macOS that line is hidden, as in the app.
- Appearance · UI size, 11 to 16 (default 12, as the app), kept as `uiSize`. It scales what the app writes in rem: text, icons, key caps, dots, the role chip, the radio, the host tile, the palette's width and the tab's widest, and the Settings sliders (a design px is `px × size / 13`, the app's rem). It does not scale what the app writes in px (the title bar, tab, pane bar and control heights, the sidebar and rail widths, the spacing and the radii) or the terminal (its text size is separate). The app has no key for it.
- Terminal · Font: the app's five (JetBrains Mono, IBM Plex Mono, Menlo / SF Mono, Consolas, System mono), kept as `termFont`, applied to every open pane at once and to new ones; the Settings preview uses it.
- Unlock (§5.14). A vault that exists and is locked (the keychain did not answer, or it uses a passphrase) shows the Unlock screen in place of the window, laid out and worded as the webview's: the mark, "Unlock your vault", the lead with the number of sessions waiting in keel serve, the banner for the vault's mode (keychain vault, `KEEL_KEYRING=off`, or a keychain that does not hold the key), the masked "Vault passphrase" field with a show/hide control, **Unlock** (↵), and the two statements (a lost passphrase cannot be recovered; running sessions keep working). A wrong passphrase shows "That passphrase doesn't open the vault." and keeps the keyboard in the field. The passphrase is sent in the one `POST /api/vault/unlock` and cleared from the field when it is sent; it is in no log, file or error. A locked vault shows Unlock whatever its first-run flag says (as the webview's gate does). A vault that still needs setup, and an unlocked vault whose first run is open, show First run (next).
- First run (§5.15). A vault that needs setup, or whose first run is open, shows the three steps in place of the window (`gate.templ` firstRunScreen and agentStep, with the flow of `gate.js`), under a progress row Vault · Hosts · Agent. **Step 1** is "Welcome to Keel": the keychain card and the passphrase card, the Passphrase and Repeat passphrase fields (with "Choose a passphrase." and "The passphrases don't match." before any request, and the server's own words after one), "Keel can't recover the vault if you lose the passphrase.", the vault file, its encryption and what it holds, **I already have a keel.vault…** (the webview's instruction text only: it quits, puts the file in the data folder and opens Keel; no file picker), and **Create vault** (`POST /api/vault/setup` with the passphrase, once). The keychain card is the webview's: it is the choice already made. With `KEEL_KEYRING=off`, or when the keychain did not answer, it is disabled with the webview's reason; on a vault the keychain made, it is the checked card and the button says **Continue**. keel serve makes a keychain vault itself, so there is no request for that choice (and a machine test cannot make one: the harness runs with `KEEL_KEYRING=off`; a person checks the keychain path once). **Step 2** is "Bring your hosts": the table of `GET /api/ssh-config/preview` with a checkbox per host (the rules of `lib/onboard.js`, with the cases of its test in `onboard_test.go`: new direct hosts start ticked, saved hosts and ProxyCommand/ProxyJump hosts start off, "Already saved", the Via flag and **Without the jump**, wildcard patterns listed apart, the notes, select all), then **Copy private keys into the vault** (one switch per key, off by default, a masked passphrase field for an encrypted key, "Enter the passphrase for <key>, or turn this key off.", "That passphrase doesn't open <key>."). **Add hosts** sends exactly the ticks and the keys turned on (`POST /api/ssh-config/import`); the result ("Added 2 hosts and 1 key. Not added: …") shows under the next step. **Back**, and **Skip, add hosts later**. The server reads the ssh config (`KEEL_SSH_DIR` in keel serve); the client never opens `~/.ssh`. Key passphrases and the vault passphrase are sent once and cleared when sent. **Step 3** is "An agent that suggests, never types": the three promises, then the box of `gate.templ` agentStep: **Provider** (Google Gemini or Not now, the radio cards; Not now is chosen), when Gemini is chosen its warning, the masked "Gemini API key" field (it takes the keyboard), "Get a key" and "Gemini API terms", and the switch "Suggest commands when I type plain language" (on). **Open Keel** sends the key once (`PUT /api/agent/keys/gemini`; keel serve does not check it with the provider, and the field is emptied as it is sent) and the switch (`PUT /api/agent/settings` with `suggestions` alone), then `POST /api/first-run/done` and the workspace; with Gemini chosen and no key it says "Paste your key, or choose Not now."; a refused save (a locked vault: "The vault is locked. Unlock it, then try again.") stays on the step with keel serve's reason. **Back**; **Set up later** saves nothing and only ends the first run (`POST /api/first-run/done`). A second window on the same daemon opens straight to the workspace. The command palette's **Import hosts from ~/.ssh/config** opens step 2 on its own (title "Import hosts", **Cancel** and Esc instead of Skip, no progress row or Back), and its result shows in the status bar.
- Tab pages. Keychain, Port forwarding, Snippets, Logs and Settings open as their own tab (one each: opening it again selects it; the tab has the page's name and glyph, cannot be renamed, closes with ⌘W or the tab menu and is reordered with the others). They are saved in `keel-native-workspace.json` as `pages` (names only, no content) with `activePage`, and come back after the session tabs, in order. The sidebar footer has **Keychain** and **Logs**; the palette has them, and Snippets, as actions and lists an open page under Open now. ⌘N on Keychain is New identity, elsewhere New host. The mechanism (`pages.go`: a `pageDefs` entry, a state type and a view) is what Forwards, Notebooks and Settings plug into.
- How Keel types for you. Keystrokes from the terminal view are the only thing that reaches a session unasked (with Sync input on, the same keys also reach the other terminals of the tab: the fifth writer, below). Everything else Keel types goes one of two ways, both written by one file, `keelclient/inject.go`, which is the only code that builds an `inject-challenge`, an `inject` or a `type-check` frame (a text frame the server answers with a one-time nonce, then the same bytes with that nonce, as `cmd/keel/web/js/pty.js` does), and each way has one caller. **Approve before type** (the dialog): `(*keelclient.Conn).ApprovedInject`, whose only caller is the dialog's Type action (`approve.go`). **One-click type** (plan 017; `docs/ui-redesign.md` §6 rule 13): `(*keelclient.Conn).DirectType`, whose only caller is `(*workspace).typeNow` (`typenow.go`), which every entry point goes through (a snippet from the palette, the sidebar, the page or its row menu; an agent proposal's card). The command is typed with **no dialog and no Enter**, and it is appended to whatever is on the prompt line; nothing runs until the user presses Enter in that pane. **keel serve decides, every time** (`internal/httpapi/typedirect.go`): it takes the command only if the client drives, the pane is not a share peer's, the pane is at its shell's prompt and not on the alternate screen, the last line does not ask for input, the command is one line with no control or invisible character and matches an exact read-only grammar (`agent.DirectSafe`: `pwd`, `df -h`, `ls [-l|-la|-lah] [PATH]`, `kubectl get RESOURCE [-n NAME|-A] [-o wide]`, `systemctl status UNIT --no-pager`, and a few more), the bytes are the snippet's or the proposal's own, and (with a Jev key) Jev rates it read-only; otherwise it answers "dialog" and nothing is written. The client only skips the round trip when the answer is certainly "dialog" (`typedirect.go`'s `directHint` is `lib/typedirect.js`'s, with the same cases). A direct type carries a fresh nonce for exactly the command, and the pane's state with it: `altScreen` and `promptLine`, read from the terminal's `Snapshot` (the plugin has no call for either; `screenOf` reads the modes 47, 1047 and 1049 and the cursor's line from it, and a terminal that cannot say is sent as the alternate screen, never as a prompt). The bytes are the command alone: no Ctrl-U, no newline (`DirectType` refuses any control or invisible character before it sends a frame, and the server refuses it too); the client never sends an Enter. One at a time per pane ("Still typing the last command into this pane."), never queued; no answer in 8 s shows "keel serve did not answer. Check the pane before you press Type again." and opens **no** dialog and does not retry (it may have been typed). After a direct type the note "Typed into <pane>. Press Enter to run." shows and the terminal gets the keyboard once no key is held (a held ↵ that pressed the button must not repeat into the pane). `guard_test.go` fails if another file builds one of the frames, if `ApprovedInject` or `DirectType` has another caller, if `typeNow` is called from anywhere but the snippet and card entry points, if a file other than `approve.go` and `typenow.go` builds an `AgentRef`, if a direct type's code adds a control character, or if `Write` is called on a connection outside the terminal view's own wrapper (`syncinput.go`). keel serve writes exactly the bytes it is given for a nonce it issued for those bytes to the driver (`internal/runtime/runtime.go` InjectTicket) and adds nothing, so the client builds them as the webview does (`term.js` paletteRunSnippet): the command gets a trailing newline if it has none, the dialog shows that text, and what is sent is Ctrl-U (it clears the line first, as the dialog says) followed by exactly that text. The dialog is the webview's (title "Type into the terminal?", its sentence, "Session:", the text in the mono font as it is, Cancel and Type; the keyboard starts on Cancel). Opening it, Escape, Cancel and a click outside send nothing; no nonce is requested before Type; the preview is asked for again every frame and when Type is pressed. Type is off, with the webview's words, when this client is following ("You are following — take or request control to type") or the session is not ready ("Session is not connected"); a missing nonce (keel serve says nothing to a bad request) ends after 2.5 s with "Session is not connected" and nothing is typed, and Keel never retries. There is no production or ⇧ rule for snippets: the webview has none (it lives in agent proposals). ### Notebooks (plan 023)

### Key caps (plan 016)

While ⌘ (Ctrl off macOS) is held 280 ms (the app's delay, `term.js:6792`) every element the app puts a cap on gets one: tabs 1 to 8 and 9 for the last, `+` (T), the sidebar toggle (B), New host (N), Settings (,) and the focused pane's Split right (⇧D), Split down (⇧E) and Focus view (⇧↵, not while disabled). Caps fade in over 120 ms (at once with reduced motion) and go at once on release, on another key, on a click and when the window loses focus; a key already down when the hold began (a menu shortcut's lost release) does not count. They show under dialogs and in text fields, as the app's do. A cap is the `kbd` type on `raised` with a `line-strong` border, a thick bottom edge and `shadow-pop`, opaque, so it reads on any ground; it **stands in for the icon or status dot** it covers, centred on it, and never a label (the app does the same with an ink-on-stage cap). Better than the app's: the same key cap look as the rest of the window (k-kbd), it reads on translucent grounds, and the caps of neighbouring pane tools no longer touch. Merely different: the app's are inverse (ink ground). A cap on a tab hides the tab's dot or icon while it shows, so nothing of it peeks out beside the cap. Settings · Terminal's text-size row shows "+ − 0" in place of the value, as the app does (the static "⌘+" hint is gone). The "W" cap on the selected tab's close button stands in for its glyph (plan 025). The app has no cap on the Agent or Share buttons.

## What is missing

Until the cutover (the plan after plan 025: the native window replaces the Wails webview, and release packaging with it) every UI change to the webview has a native counterpart to build; these three lists are the parity ledger.

### Not built, the app has it

Each with its reason and a size. Anything not listed here is built or is not in the app.

- **Previous command / Next command** (the palette actions, shell integration marks). The terminal plugin keeps the marks (OSC 133) for itself and exposes no call for them (`plugins/terminal` has `Search`, `Snapshot` and the prompt row for Home-key handling, nothing that lists or jumps to a mark). Waits for the plugin.
- **The terminal's own right-click menu with Find, Split right, Split down and Close pane** (the app's `TermMenu`). With Right-click set to Menu the plugin shows its own menu (Copy, Paste, Select all, Clear) and has no hook to add items; a menu of the window's own cannot copy the selection or select all (the plugin returns neither). The setting applies to new panes only (the plugin takes it when a terminal is made).
- **Find bar Match case.** The plugin's search ignores the case of ASCII letters and reports only the count and the selected match's place (`SearchStatus`), not the matched text, so the client cannot filter matches itself. Waits for a case option in the plugin.
- **The Logs page's live stream.** The page reads on open, on select, on Refresh and when the vault's `rev` changes; the app streams over Datastar (`/ui/...` SSE, `internal/httpapi/uistream.go`), which this client does not speak. A forward's or a session's log line shows within the 3 s poll only when something else bumps `rev`. About 150 lines with tests.
- **Menu icons of the agent cards' right-click menus** (cardmenu.js gives each item a glyph): MyGo's menu icons are images made once with `mygo.NewMenuIconSVG`, which needs the window system; no native menu draws an icon anywhere today (plan 026 looked: nothing to reuse), so the five card menus would be the first; about 80 lines.
- **Notebook History times in the system locale's clock** (the app's `toLocaleTimeString`): the window knows only a locale tag (`mygo.App.Locale`) and has no time formatter for it without a new dependency, so History says "today 14:05" on a 24-hour clock.
- **Rarely seen differences left for polish**: the host key dialog's key type line is the window's own addition; Unlock's "Try the keychain again next time" (a checked, disabled box with no effect); the Keychain page's fingerprint, comment, public key and algorithm badge are not in the app's detail either (the server redacts them).

### Different on purpose

- The notebook is read rendered and edited as Markdown source; a notebook over 64 KiB opens in Edit ("Notebooks (plan 023)").
- Right-click in the terminal, Copy on select and the other terminal settings are the plugin's: Copy on select and the text size apply at once, Right-click applies to new panes; the plugin's menu is fixed.
- Window opacity and blur are native-only; Font smoothing has no meaning for MyGo's own text; the About lead says "a native client".
- The agent's markdown is shown as the characters the model wrote; ⇧↵ on a focused Type button is not offered (MyGo gives a keyboard press no modifier).
- A joined tab takes no snippet and no Approve before type: the app's `termTarget` needs a runtime id a joined pane has not, so "Open a session first" is the app's answer too (not a difference; recorded because the old list named it).
- The one-click read-only group step (§6 rule 13) stays unbuilt: the spec still says "not accepted", so every group step goes through the dialog.
- The palette says "No matching commands" above its Ask row when the query matches nothing; the app's list holds only the row.
- Preferences live in two places while `keel app --webview` exists: the webview's localStorage and `keel-native.json`; they do not sync, and the native client cannot read the webview's, which lives in the WKWebView profile. **Moving from the webview to the native window (cutover stage 1).** What carries over, because `keel serve` holds it: hosts, folders, identities and the vault, snippets, notebooks, runbooks and notes, port forwards, the agent's settings and keys (provider, model, detection, suggestions, scrollback, redaction, history, Allow Claude Code), the signal server (Settings · Sharing), and the running sessions (they become tabs after the saved ones). What a person sets again, once, in Settings: **Theme** (`keel-theme`), **Terminal** font, text size, Copy on select and Right-click (`keel-term`), **Appearance** UI text size, Window opacity and blur, the sidebar's width and its Hosts/Panes segment, whether the sidebar and the agent panel are open (`keel-ui`), the **name** others see when you share (`keel-name-custom`; `KEEL_NAME` and `keel app --name` still work), and the tabs and splits of the last window, the recent hosts, the recently closed tabs and the collapsed folders (all of them rebuild themselves as the window is used). The webview keeps its own copy of all of these for as long as `--webview` stays.
- "The herd" (the app's `/ws/herd` socket of session snapshots and spawn, kill, update events): this client reads `GET /api/sessions` when the window opens and each pane's own connection reports its state, presence and end, so it needs no client code of its own. What differs: a session killed from another window shows "Session ended" with Close in this window, where the app closes the pane at once; the host rows' session counts follow the panes of this window, as the app's `syncHostLive` does.
